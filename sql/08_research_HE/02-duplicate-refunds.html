מחלקת הכספים שמה לב שסך ההחזרים גבוה מהצפוי. החשד: אותה הזמנה הוחזרה ללקוח יותר מפעם אחת.

שאלה
אילו הזמנות מופיעות בטבלת refunds יותר מפעם אחת?

הזמנה תקינה מוחזרת פעם אחת לכל היותר. אם אותו order_id מופיע בטבלת ההחזרים פעמיים — זה החזר כפול, וצריך לתפוס אותו.

מה צריך להציג?

  • מספר ההזמנה
  • שם הלקוח שביצע את ההזמנה
  • כמה פעמים ההזמנה הוחזרה

הטבלאות והנתונים

  • customersהלקוחות — מספר ושם
  • ordersההזמנות, ולכל אחת הלקוח שביצע אותה
  • refundsכל שורה היא החזר אחד, עם order_id של ההזמנה שהוחזרה

הריצו את שתי הפקודות למטה ב־DB Browser for SQLite (לשונית Execute SQL) — קודם יצירת הטבלאות ואחר כך הכנסת הנתונים — ואז כתבו את השאילתה שלכם.

1. יצירת הטבלאות
CREATE TABLE customers (
  id    INTEGER PRIMARY KEY,
  name  TEXT NOT NULL
);

CREATE TABLE orders (
  id          INTEGER PRIMARY KEY,
  customer_id INTEGER NOT NULL,
  total       REAL NOT NULL,
  FOREIGN KEY (customer_id) REFERENCES customers(id)
);

CREATE TABLE refunds (
  id          INTEGER PRIMARY KEY,
  order_id    INTEGER NOT NULL,
  amount      REAL NOT NULL,
  refunded_at TEXT NOT NULL,
  FOREIGN KEY (order_id) REFERENCES orders(id)
);

שלבי הפתרון

נסו קודם לבד, ואם נתקעתם — לכו שלב אחרי שלב. יש יותר מדרך אחת נכונה; העיקר שהתוצאה נכונה.

  1. הבינו מה מחפשים

    מחפשים order_id שמופיע יותר מפעם אחת בטבלת refunds.

  2. ספרו כמה פעמים מופיעה כל הזמנה

    התחילו רק מטבלת refunds: קבצו לפי order_id (GROUP BY order_id) וספרו עם COUNT(*). שימו לב — מקבצים לפי ההזמנה ולא לפי הלקוח.

  3. השאירו רק את הכפולות

    כדי להשאיר רק הזמנות שהוחזרו יותר מפעם אחת משתמשים ב־HAVING COUNT(*) > 1. למה HAVING ולא WHERE? כי WHERE מסנן שורות לפני הקיבוץ, ואילו הספירה מתקבלת רק אחרי GROUP BY.

  4. הגיעו אל שם הלקוח

    בטבלת refunds יש רק מספר הזמנה. הדרך ללקוח עוברת דרך שני JOIN: refunds → orders → customers (קודם לפי order_id, ואחר כך לפי customer_id).

  5. הציגו את התוצאה

    בחרו להציג את מספר ההזמנה, שם הלקוח ומספר ההחזרים (תנו לו שם ברור עם AS).

💡 לזכור

WHERE מסנן שורות לפני הקיבוץ. HAVING מסנן קבוצות אחרי הקיבוץ.
