Regular Expressions 🔍

Checking whether text "looks right" — an email, a phone number, a strong password — takes a loop and five boolean variables by hand. A regular expression describes the whole rule as one pattern string, and the re module checks it for you. It is a tiny language of its own: about ten symbols, and this page teaches all of them.

03_str_regex.py
import re phone = "054-1234567" print(re.match(r'^05\d-?\d{7}$', phone)) # <re.Match object ...>
1

The idea, and the r'…' string

A pattern is just a string — but a string with special characters in it. It always gets written with an r in front:

import re pattern = r'\d\d\d' # "three digits" print(re.findall(pattern, "call 054 or 987"))
['054', '987']
💡 Why the r? It makes a raw string: Python leaves every backslash exactly as you typed it. Without it, Python would first try to read \d as an escape code (like \n is a new line) and your pattern would arrive at re damaged. Always write patterns as r'…' — it costs one character and saves hours.
💡 A pattern with no special characters is simply the text itself: re.search(r'World', 'Hello World') finds World. Everything below is about the characters that mean something more than themselves.

The five functions of re

Pick the one that matches the question you are actually asking:

FunctionQuestion it answersGives you back
re.match(p, s)does the text start with this?a Match object, or None
re.search(p, s)is this anywhere in the text?a Match object, or None
re.findall(p, s)give me all of thema list of strings (empty if none)
re.sub(p, new, s)replace every matcha new string
re.fullmatch(p, s)does the whole text fit?a Match object, or None
import re text = "Hello World" print(re.match(r'World', text)) # None - it is not at the START print(re.search(r'World', text)) # found it print(re.findall(r'\d+', "a1b22c333")) print(re.sub(r'\s+', ' ', "too many spaces"))
None <re.Match object; span=(6, 11), match='World'> ['1', '22', '333'] too many spaces
⚠️ re.match only ever looks at the beginning. This surprises everyone once. If you mean "somewhere in the text", you want re.search.
3

🐞 What a match really is — never == True

This is the bug we hit in class. It printed Invalid for every password, even correct ones:

if re.match(pattern, password) == True: # always False! print('Valid') else: print('Invalid')

Because re.match does not return True. It returns a match object when the pattern fits, and None when it does not:

>>> re.match(pattern, 'MyDogEats42!x') <re.Match object; span=(0, 13), match='MyDogEats42!x'> >>> re.match(pattern, 'MyDogEats42!x') == True False ← a Match object is not the value True >>> bool(re.match(pattern, 'MyDogEats42!x')) True ← but it IS truthy
if re.match(pattern, password): # ✔ the right way print('Valid') else: print('Invalid')
⚠️ Put the value straight in the if and Python asks "is there something here?" instead of "is this exactly the value True?". A match object counts as yes, None counts as no. Same rule as boolean variables: if is_adult:, never if is_adult == True:.
4

Character classes — [ ] means "one of these"

Square brackets are a menu: match exactly one character, any of the ones listed.

print(re.findall(r'[aeiou]', "python course")) # the vowels print(re.findall(r'[a-z]+', "Hello Python 3")) # runs of small letters print(re.findall(r'[^0-9]', "a1b2")) # NOT a digit print(re.findall(r'c.t', "cat cot cut ct c t")) # . = any one character
['o', 'o', 'u', 'e'] ['ello', 'ython'] ['a', 'b'] ['cat', 'cot', 'cut', 'c t']
WrittenMeans
[abc]one character: a, b or c
[a-z]any one lowercase letter — a range
[A-Za-z0-9]any letter or digit — ranges stack up
[^0-9]anything that is not a digit. A ^ as the first character inside the brackets flips the whole menu
.any single character at all (except a new line)
⚠️ ^ has two completely different jobs. Inside [ ] it means "not". Outside it means "start of the text" (step 6). Same symbol, opposite worlds.
💡 The dot is greedy about meaning too — to match a literal dot you must escape it: r'3\.10' matches only 3.10, while r'3.10' also matches 3x10 and 3-10.
5

The shortcuts — \d \w \s

Three classes are so common they got a one-letter name. Capitalise the letter to mean the opposite:

ShortcutSame asMeaning
\d[0-9]a digit
\D[^0-9]not a digit
\w[A-Za-z0-9_]a "word" character — letter, digit or underscore
\W[^A-Za-z0-9_]not a word character (space, !, - …)
\s[ \t\n]a whitespace — space, tab or new line
\S—not a whitespace
print(re.findall(r'\w+', "hi_there you-2")) print(re.findall(r'\W', "a b!c")) print(re.findall(r'\d+', "My phone is 054-1234567"))
['hi_there', 'you', '2'] [' ', '!'] ['054', '1234567']
💡 Notice \w counts the underscore as a letter but not the hyphen — which is why hi_there stayed whole and you-2 split in two.
6

How many? — * + ? {n}

A quantifier sits after the thing it counts and says how many times it may repeat:

SymbolHow manyExample
*zero or moreab* → a, ab, abbb
+one or moreab+ → ab, abbb (not a)
?zero or one — "optional"colou?r → color, colour
{3}exactly 3\d{3} → 054
{2,4}between 2 and 4\d{2,4}
{12,}12 or more.{12,}
print(re.findall(r'ab*', 'a ab abb abbb')) print(re.findall(r'ab+', 'a ab abb abbb')) print(re.findall(r'colou?r', 'color colour')) print(re.findall(r'\d{2,4}', '1 12 123 12345'))
['a', 'ab', 'abb', 'abbb'] ['ab', 'abb', 'abbb'] ['color', 'colour'] ['12', '123', '1234']
💡 Read the last line carefully: 12345 gave 1234, not 12345 — the quantifier stopped at its maximum of 4. And the lonely 1 never appeared, because the minimum is 2.
💡 + is the one you will reach for most: \d+ = "a number", \w+ = "a word", \s+ = "any run of spaces".
7

Anchors — ^ start and $ end

Without anchors a pattern is happy to match a small piece hiding inside a bigger string. ^…$ demands that the whole text fits — which is exactly what you want when validating input.

print(re.match(r'^Hello', 'Hello world')) # found print(re.match(r'world$', 'Hello world')) # None - match looks at the start # the difference anchors make print(bool(re.match(r'\d{3}', '123abc'))) # True - only checked the front print(bool(re.match(r'^\d{3}$', '123abc'))) # False - the whole thing must be 3 digits
<re.Match object; span=(0, 5), match='Hello'> None True False
💡 Rule of thumb: searching for something inside text → no anchors. Validating a whole value (email, phone, password) → always wrap it in ^…$.
8

Groups ( ) — pulling the pieces out

Parentheses do two jobs: they keep a quantifier's reach under control, and they remember the piece they matched so you can read it back.

m = re.search(r'(\d{3})-(\d{7})', 'call 054-1234567 now') print(m.group(0)) # the whole match print(m.group(1)) # the first ( ) print(m.group(2)) # the second ( )
054-1234567 054 1234567
⚠️ m.group(...) only works when there was a match. On a failed search m is None and you get AttributeError: 'NoneType' object has no attribute 'group'. Always check first: if m: — then read the groups inside.
💡 Groups also change what findall gives you: with one or more ( ) in the pattern, it returns the groups instead of the whole matches. Surprising the first time it happens.
9

Lookahead (?=…) — the password pattern, decoded

A lookahead asks "is this somewhere ahead?" without consuming any characters. That is what lets you stack four independent demands on the same text — the trick behind every password rule:

pattern = r'^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z0-9]).{12,}$' password = input("Password: ") if re.match(pattern, password): print('Valid') else: print('Invalid')
^start (?=.*[a-z])a small letter (?=.*[A-Z])a capital (?=.*\d)a digit (?=.*[^A-Za-z0-9])a special char .{12,}12+ characters $end
✔MyDogEats42!xhas all four, 13 characters
✘mydogeats42!xno capital letter
✘MyDogEats42xno special character
✘Short1!aonly 8 characters
💡 Inside each lookahead, .* means "skip anything", so (?=.*\d) reads as "somewhere after here, there is a digit". Because a lookahead does not move the cursor, all four run from the same spot — and then .{12,} does the actual consuming.
💡 Compare with doing it by hand: three or four boolean variables and a for loop over the characters. The loop version is longer, but it can tell the user which rule failed. The regex only says yes or no — that is the real trade-off.
10

Four patterns worth stealing

📧 An email address

email = r'^[\w\.-]+@[\w\.-]+\.\w{2,}$'
✔danny@gmail.com
✔danny.cohen@my-site.co.il
✘danny@@gmail.comtwo @
✘danny.gmail.comno @ at all

📱 An Israeli mobile number

phone = r'^05\d-?\d{7}$' # the -? makes the dash optional
✔054-1234567
✔0541234567dash is optional
✘05-41234567dash in the wrong place
✘054-123456only 6 digits after

📅 A date, dd/mm/yyyy

date = r'^\d{2}/\d{2}/\d{4}$'
✔03/08/2026
✘3/8/2026needs the leading zeros

🎨 A hex colour

colour = r'^#[0-9a-fA-F]{6}$'
✔#0D9488
✘#abconly 3 characters
✘#GGGGGGG is not a hex digit
⚠️ Even the email pattern above accepts things a real mail server would reject, and rejects a few exotic addresses that are actually legal. That is normal — a regex is a quick sanity check on the shape of a value, not a proof that it exists.
11

Two more things worth knowing

Ignore the case instead of writing [Pp][Yy]…:

print(bool(re.search(r'python', 'I love Python', re.IGNORECASE)))
True

Search and replace — re.sub is .replace() with a pattern instead of fixed text:

print(re.sub(r'[aeiou]', '*', 'python course')) print(re.sub(r'\s+', ' ', 'too many spaces'))
pyth*n c**rs* too many spaces
💡 When the thing you are looking for is fixed text, do not reach for regex at all — '_' in name, name.startswith('05') and name.replace('_', '-') are shorter, faster and far easier to read. Regex earns its keep only when the rule has a shape.
