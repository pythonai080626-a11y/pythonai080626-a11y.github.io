01

Parameters — the slots in the def line

A function with empty () always does exactly the same thing. Put a name inside those brackets and the function gains a slot: a variable that does not exist until somebody calls the function and fills it.

parameters.py
# one slot ─────────────────────────────────────
def say_hello(name):
    print('Hello,', name)

say_hello("Danny")          # Hello, Danny
say_hello("Mor")            # Hello, Mor

# two slots, filled left to right ──────────────
def rectangle_area(width, height):
    return width * height

rectangle_area(5, 10)      # width=5, height=10  → 50
rectangle_area(10, 5)      # width=10, height=5  → 50, but not the same slots
The error you will meet
Call rectangle_area(5) and Python stops you: TypeError: rectangle_area() missing 1 required positional argument: 'height'. A slot with no default must be filled.
02

Default values — a slot that fills itself

Write = in the def line and the slot gets a fallback. Now the caller may pass a value, but does not have to. One function, two ways to call it.

defaults.py
def say_hello(name="incognito"):
    '''
    say hello to user
    :param name: name of the user. default is "incognito"
    :return: None
    '''
    print('Hello,', name)

say_hello()                  # Hello, incognito   ← nothing passed, default used
say_hello("Danny")           # Hello, Danny       ← default ignored
say_hello("Mor")             # Hello, Mor

# every slot can have one ──────────────────────
def add(x=0, y=0):
    return x + y

add()                        # → 0    both defaults
add(5)                       # → 5    x=5, y still 0
add(5, 10)                   # → 15
Order rule
Slots without a default must come first. def f(a, b=0) is fine; def f(a=0, b) is a SyntaxError.
Say it in the docstring
If a parameter has a default, write it down: :param name: ... default is "incognito". The next reader should not have to guess.
03

Using = when you call it

The = shows up in two completely different places, and this is where people get lost. In the def line it sets a default. At the call it names which slot you are filling.

in_the_def.py
# = here means "if nobody passes one"
def print_square(x=0):
    print(x ** 2)

# the default is set ONCE,
# when the def line is read.
in_the_call.py
# = here means "this one goes in x"
print_square(x=5)     # 25
print_square(5)       # 25 - same thing
print_square()        # 0  - default

# nothing is being assigned
# to a variable called x here.

Naming the slot buys you two things: the call reads like a sentence, and the order stops mattering.

keywords.py
def rectangle_area(width, height):
    return width * height

rectangle_area(5, 10)                      # positional  → 50
rectangle_area(width=5, height=10)       # by name     → 50
rectangle_area(height=10, width=5)       # backwards!  → 50, still right

# mixing is allowed - positional first, named after
rectangle_area(7.5, height=12)             # → 90.0

# but not the other way round
# rectangle_area(width=7.5, 12)   ← SyntaxError
Why bother
Six months from now, book(4, 2, 1) means nothing. book(adults=4, kids=2, rooms=1) still means something. Name them the moment a call stops being obvious.
04

return — sending the answer back

Printing shows a value to a human. Returning hands it to the rest of the program, which can store it, add to it, or pass it on. A function that only prints is a dead end.

returning.py
def add(x=0, y=0):
    '''
    add two numbers
    :param x: 1st number
    :param y: 2nd number
    :return: sum of x + y
    '''
    sum_xy = x + y
    return sum_xy

result = add(x=5, y=10)     # catch it in a variable
print('add returned', result)  # add returned 15
print(add(5, 10))              # or use it on the spot → 15

# sum_xy only existed inside. print(sum_xy) → NameError

return also stops the function on the spot. Nothing after it runs — which is what makes these two versions identical:

with_else.py
def max_number(a=0, b=0):
    if a > b:
        return a
    else:
        return b
without_else.py
def max_number(a=0, b=0):
    if a > b:
        return a
    return b

# if a > b we already left.
returning_anything.py
# a function can hand back any type it likes
def get_even_odd(a=0):
    '''
    :param a: a number
    :return: "even" or "odd"
    '''
    if a % 2 == 0:
        return "even"
    return "odd"

print(get_even_odd(0))     # even
print(get_even_odd(7))     # odd
print(get_even_odd(-3))    # odd

# ...even a whole dictionary
def count_letters(text):
    d = {}
    for c in text:
        if c not in d:
            d[c] = 1
        else:
            d[c] += 1
    return d

print(count_letters('missiiiissippi'))
# {'m': 1, 'i': 7, 's': 4, 'p': 2}
05

Functions that return nothing

Leave out return and the function still hands something back: None. Python always returns something. None is the value that means “there was no answer” — and it is a real value you can print, store and test.

none.py
def greeting():
    '''
    printing hello
    :return: None
    '''
    print('hello, danny')

greeting()               # hello, danny        ← it printed

x = greeting()          # hello, danny        ← it printed again
print(x)                # None                ← and gave back nothing

# a function body that does nothing at all still needs a line
def hi():
    '''
    this is my documentation
    :return:
    '''
    pass                  # a placeholder - "nothing here yet"

This is not a beginner’s curiosity — it is the difference between the two kinds of method you already use every day.

gives_back_vs_changes.py
d = {1: 'a'}
res = d.pop(1)         # pop RETURNS what it removed
print(res)                # a

a = [4, 3]
out = a.sort()          # sort changes the list IN PLACE
print(out)                # None   ← nothing came back
print(a)                  # [3, 4] ← but the list did change
The classic bug
a = a.sort() throws your list away and leaves you holding None. Ask yourself for every function you write and every method you call: does this give something back, or does it change something in place? It is almost never both.
06

Say what goes in and what comes out

Now that functions have parameters and return values, the docstring has real work to do. Three lines, every time — what it does, what each parameter is, and what comes back.

docstring.py
def rectangle_area(width, height):
    '''
    calculate area of rectangle
    :param width: width of rectangle
    :param height: height of rectangle
    :return: area of rectangle
    '''
    return width * height

help(rectangle_area)     # reads it straight back to you
:param
One line per slot. Say what it means and, if it has a default, what that default is.
:return
What comes back — and write None when the function only prints. That is information, not an empty line.
07

Quick reference

ConceptSyntaxNotes
Parameter def f(name): A slot. Must be filled at the call, or TypeError.
Two parameters def f(w, h): Filled left to right. f(5, 10) → w=5, h=10.
Default value def f(x=0): Caller may skip it. Defaults come after non-defaults.
Keyword argument f(x=5) Names the slot at call time. Order stops mattering.
Mixing f(7.5, height=12) Positional first, named after. Never the reverse.
Return a value return x + y Hands it back and exits the function immediately.
Catch it r = add(5, 10) Or use it on the spot: print(add(5, 10)).
No return print(greeting()) Prints None. Every function returns something.
Empty body pass A placeholder so the indented block is not empty.
Docstring :param / :return First thing in the body. help(f) reads it back.
