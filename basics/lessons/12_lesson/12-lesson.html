01_str.py

The str Type — Text That Knows Things About Itself

You have been using strings since lesson 3. Today we find out that a string carries a whole toolbox around with it.

name = 'Danny' # input('name?') print(type(name))
<class 'str'>
len() — how many characters
print('length of Danny is', len(name)) print(f'length of Danny is {len(name)} characters')
length of Danny is 5 length of Danny is 5 characters
len is a plain function — the same one you will later use on lists. It goes around the value: len(name). And remember from lesson 11 that an f-string can hold a whole expression, so {len(name)} works exactly as you would hope.
The dot — calling a method

Everything else today is written the other way around: the value comes first, then a dot, then the name of what you want.

name = 'danny' print(name.upper()) # DANNY ← the normal way print(str.upper(name)) # DANNY ← the same thing, written the long way
DANNY DANNY
Both lines do exactly the same work. name.upper() is the version you will write for the rest of your life; str.upper(name) is shown once so you can see what the dot really means — "run the str function called upper, on this string". Note the empty parentheses: upper(), not upper. Without them nothing runs.
⚠️ A string never changes

This is the single most important idea of the lesson. A method does not edit your string — it hands you back a new one.

name = 'danny' name.upper() # ← the result is thrown away! print(name) # danny - nothing happened name = name.upper() # ← store it back, now it counts print(name) # DANNY
'danny' .upper() → 'DANNY' (a brand new string)
If a line that calls a method does not print the result or assign it to a variable, that line did nothing at all. This is the number-one beginner bug with strings.

The Method Tour 🧰

Nine slides, one idea each. Use prev / next at the bottom.

1

.upper() and .lower()

name = 'danny' print(name.upper()) # DANNY yossi = 'YOSI' print(yossi.lower()) # yosi
DANNY yosi
The classic real use: comparing user input. answer.lower() == 'yes' accepts Yes, YES and yEs in one line, instead of an if with four ors.
2

.swapcase() — flip every letter

print("AasdasBcccC".swapcase()) print("AasdasBcccC".swapcase().swapcase()) # back to the start
aASDASbCCCc AasdasBcccC
Two dots in a row is chaining: the first swapcase() produces a new string, and the second one runs on that. Read it left to right, like a little assembly line. Swapping twice returns the original — a nice way to prove the string itself was never touched.
3

.capitalize() vs .title()

text8 = "hello, world!! Good morning" print(text8.capitalize()) # only the FIRST letter text9 = "hello, world!! good morNing" print(text9.title()) # EVERY word
Hello, world!! good morning Hello, World!! Good Morning
Look carefully at capitalize(): it did not only add a capital H — it also pushed the existing capital G of Good back down to lowercase. Both methods force everything else to lowercase.
4

.replace(old, new) — swap text

sentence = "Hello, World!!" print(sentence.replace("World", "Universe")) print(str.replace(sentence, "World", "Universe")) # same thing
Hello, Universe!! Hello, Universe!!
It replaces every occurrence, not just the first. And if the old text is not there at all, nothing happens — no error, you simply get the same text back.
5

.split(sep) — one string → many

sentence: str = "Hello, World!! good morning" print(sentence.split()) # no argument = split on spaces sentence = "Hello*python*class*vip" print(sentence.split('*')) # split on a * instead
['Hello,', 'World!!', 'good', 'morning'] ['Hello', 'python', 'class', 'vip']
Those square brackets are a list — the next big type we will meet. For today just notice the shape: split cuts the text everywhere it sees the separator and hands you the pieces. Notice also sentence: str = "…" — an optional type hint; it changes nothing at run time, it just tells you (and PyCharm) what belongs in that variable.
6

.strip() — trim the edges

sentence = " Hello, World!! " print(f"'{sentence}'", 'strip=', sentence.strip()) print(f"'{sentence}'", sentence.split())
' Hello, World!! ' strip= Hello, World!! ' Hello, World!! ' ['Hello,', 'World!!']
strip() removes spaces from the start and the end only — spaces in the middle stay. The quotes around '{sentence}' in the f-string are a trick worth stealing: without them you cannot see the spaces at all.
Chaining three methods
user_input = " jOhN_dOe_2026 " print(user_input.strip().lower().replace("_", "-"))
john-doe-2026
' jOhN_dOe_2026 ' → strip → 'jOhN_dOe_2026' → lower → 'john_doe_2026' → replace → 'john-doe-2026'
7

.startswith() / .endswith()

sentence = "Hello, World!! good morning" print('startswith("Hello") ?', sentence.startswith("Hello")) print('endswith("morning") ?', sentence.endswith("morning"))
startswith("Hello") ? True endswith("morning") ? True
These give you back a bool — exactly the True/False value from lesson 11. So you can name it and use it: is_greeting = sentence.startswith("Hello"), then if is_greeting:.
8

The is… family — questions that answer True / False

print("1234".isalpha()) # False - digits are not letters print("abcd".isalpha()) # True print("abcd_".isalpha()) # False - _ is not a letter print("abcd1*".isalpha()) # False print("1234".isdigit()) # True print("abcd1".isdigit()) # False - one letter is enough to fail print("Aab".islower()) # False print("aab".islower()) # True print("ABC".isupper()) # True print(" ".isspace()) # True
"python3".isalpha()
False
"12 34".isdigit()

" ".isspace()

"HELLO".isupper()
True
"hi".islower()

The rule is every character must pass. "python3" fails isalpha() because of one digit; "12 34" fails isdigit() because of one space. There is no "mostly".
isdigit() is the honest way to check user input before int(). int('abc') crashes with ValueError — if answer.isdigit(): lets you ask first.
9

.zfill() and .center() — padding

print("42".zfill(5)) # 00042 print('123456789ABC') # a ruler, to count the width print(f"{'Hello!'.center(11, '-')}hi") # fill with dashes print('Hello!'.center(11, ' ')) # fill with spaces
00042 123456789ABC ---Hello!--hi Hello!
center(11, '-') means "make it 11 characters wide, pad with -". 'Hello!' is 6 long, so 5 dashes are shared — and when the padding does not divide evenly, Python is allowed to put the extra one on either side. Do not count on perfect symmetry.
Two ways to say the same thing
Method on a stringf-string specResult
"42".zfill(5)f"{42:05}"00042
'hi'.center(10)f"{'hi':^10}"    hi    
'hi'.center(10, '*')f"{'hi':*^10}"****hi****
The method works on a string; the f-string spec works on anything, including numbers, without converting first. That is why zfill needed the quotes around "42".

A String Is a Row of Characters — Index & Slicing

Every character sits at a numbered position. Counting starts at 0, and you can also count backwards from the end with negative numbers.

"Python"
P0-6
y1-5
t2-4
h3-3
o4-2
n5-1
text = "Hello python course" # 0123456789... print(text[0]) # H - the first character print(text[-1]) # e - the LAST character
H e
[-1] is the everyday way to reach the last character. It saves you from writing text[len(text) - 1], and it still works after the text changes length.
Slicing — [start:stop]

Two numbers with a colon give you a piece of the string. The start is included, the stop is not — exactly like range() in lesson 6.

"Python"[2:5] → 'tho'
P0
y1
t2
h3
o4
n5stop
text = "Hello python course" print(text[0:3]) # Hel - 0,1,2 (3 not included) print(text[1:4]) # ell print(text[0:5]) # Hello print(text[:5]) # Hello - leave start out = from the beginning print(text[0:]) # the whole string - leave stop out = to the end print(text[:]) # the whole string
Hel ell Hello Hello Hello python course Hello python course
The third number — [start:stop:step]
print(len(text)) # 19 print(text[1:8:2]) # take every 2nd character between 1 and 8 print(text[::2]) # every 2nd character of the whole string print(text[::-1]) # step BACKWARDS = reversed!
19 el y Hlopto ore esruoc nohtyp olleH
[::-1] is the one to memorise: no start, no stop, step of -1 — "walk the whole string backwards". It is how Python programmers reverse text, and it is today's third exercise.
A real use — is it a palindrome?
msg = "step on no pets" print(msg == msg[::-1]) if msg == msg[::-1]: print('reverse equals original') else: print('reverse not equals original')
True reverse equals original
Careful with the last index. "Hello python course" has len 19, so the valid indexes are 0…18. Writing text[19] gives IndexError: string index out of range. But slicing is forgiving — text[0:19] and even text[0:500] are perfectly happy. Indexing is strict, slicing is not.

Looping Over a String — Two Ways

The task: print every character of a sentence on its own line, but skip the spaces.

Way 1 — by index, with range
mech = "Python Core Study Mechanics" for i in range(0, len(mech)): if not mech[i].isspace(): # same as: if mech[i] != ' ' print(mech[i])
range(0, len(mech)) — not a hard-coded range(0, 27). The moment you change the sentence, a hard-coded number is wrong and you get an IndexError. len() keeps the loop honest.
Way 2 — for-each, straight over the characters
for c in "hello": # c is the character itself print(c) for c in mech: if not c.isspace(): print(c)
h e l l o P y t h o n C ... and so on
This is new and it is a big deal. Until today, for always walked over range(...) — a run of numbers. It turns out for can walk over a string too, handing you one character per round. No index, no len, no square brackets.
for i in range(len(s))for c in s
What the variable holdsa number — the positionthe character itself
Getting the characters[i]c
Use it when…you need to know where you areyou only care what is there
Prefer the for-each version. It is shorter, it cannot go out of range, and it says exactly what you mean.
02_str_printf.py

f-strings — The Specs We Were Still Missing

Lesson 11 covered .2f, < > ^, ,, 05d, .1% and +. Today's file adds four more that finish the picture.

1 · A width on its own — and the default direction
x = 5 print(f"{x:5}") # minimum width 5 text = "Python" print(f"|{text:10}|")
5 |Python |
A width with no alignment symbol does not mean "left". Python's default depends on the type: numbers go right, text goes left. If you are building a table with a mix of both, always write the <, > or ^ yourself — otherwise your columns fight each other.
2 · A fill character — put it before the alignment
x = 5 print(f"{x:*<5}") # 5**** print(f"{x:*>5}") # ****5 print(f"{x:*^5}") # **5**
5**** ****5 **5**
The order inside the spec is fill, then alignment, then width: * ^ 5. Any single character works — . for a menu's dotted line, - for a separator, 0 for zero padding (which is exactly what :05 is short for).
3 · .5 on text — cut it short
text = "HelloWorld" print(f"{text:.5}") # Hello - keep at most 5 characters print(f"{text[:5]}") # Hello - the same, using a slice
Hello Hello
Same dot, different meaning. On a number, .5 means "5 digits after the point"; on text it means "at most 5 characters". Handy for keeping a long name from breaking a column.
4 · Width and precision together
pi = 3.14159 print(f"{pi:8.2f}") # 8 wide, 2 decimals
3.14
Read it as two separate instructions glued together: 8 = the total width of the column, .2f = the number itself. This is the spec that makes a column of prices line up on the decimal point.
And the ones you already knew
x = 42 print(f"{x:05}") # 00042 print(f"{10:+}") # +10 print(f"{-10:+}") # -10 pi = 3.1415926 print(f"{pi:.2f}") # 3.14 print(f"{pi:.4f}") # 3.1416 print(f"{123456789:,}") # 123,456,789 print(f"{0.375:.2%}") # 37.50%
00042 +10 -10 3.14 3.1416 123,456,789 37.50%
The full reference lives on the f-string Tricks topic page — it now includes today's four additions.

Regular Expressions — A First Look 🔍

Checking a password by hand needs a loop and four boolean variables. A regular expression ("regex") describes the whole rule as one pattern string, and the re module checks it for you.

import re password = input("Password: ") # Regular Expression pattern = r'^(?=.*[a-z])(?=.*[A-Z])(?=.*\d)(?=.*[^A-Za-z0-9]).{12,}$' if re.match(pattern, password): print('Valid') else: print('Invalid')
Password: hello Invalid
Password: MyDogEats42!x Valid
Reading the pattern piece by piece
^ (?=.*[a-z]) (?=.*[A-Z]) (?=.*\d) (?=.*[^A-Za-z0-9]) .{12,} $
PieceWhat it demands
r'…'A raw string. Without the r, Python would try to interpret \d as an escape code. In a regex you always want the backslash left alone — so patterns are always written r'…'.
^ … $Start of the text … end of the text. Together they mean "the whole string must fit", not just some part of it.
(?=.*[a-z])"Somewhere ahead there is a lowercase letter." [a-z] is a range of characters and .* is "anything, any amount".
(?=.*[A-Z])…and an uppercase letter.
(?=.*\d)…and a digit. \d is the shortcut for "any digit".
(?=.*[^A-Za-z0-9])…and a special character. The ^ inside square brackets means not — so: something that is not a letter and not a digit.
.{12,}At least 12 characters in total. {12,} is "12 or more".
🐞 The bug that was in the file

The version we typed in class had this line, and it printed Invalid for every password — even correct ones:

if re.match(pattern, password) == True: # always False! print('Valid')

Why? Because re.match does not return True. It returns a match object when the pattern fits, and None when it does not:

>>> re.match(pattern, 'MyDogEats42!x') <re.Match object; span=(0, 13), match='MyDogEats42!x'> >>> re.match(pattern, 'MyDogEats42!x') == True False ← a Match object is not the value True >>> bool(re.match(pattern, 'MyDogEats42!x')) True ← but it IS truthy
This is lesson 11's rule earning its keep: never write == True. Just put the value in the if — if re.match(pattern, password): — and Python asks "is there something here?" instead of "is this exactly the value True?". A match object counts as yes; None counts as no.
Regex is a whole language of its own and you are not expected to write one from memory today. Recognise it, know that re.match is how you use it, and know it returns a match-or-None. When you want the whole picture — \d, \w, [a-z], the + * ? counters, groups, and ready-made patterns for email / phone / date — it is all on the Regular Expressions topic page.

Fix the f-string

name = "Danny" print(f"{name} your name is in length len(name)") # prints the words "len(name)" print(f"{name} your name is in length {len(name)}") # ✔
Danny your name is in length 5
Outside the curly braces, everything is literal text. Anything you want evaluated has to be inside { }.
2

An ID card, using center

first_name = "Petros" last_name = "Borchardt" id_num = "63 251283 B 185" phone = "0419-0288803" print(f"| {(last_name + ', ' + first_name).center(22)} |") print(f"| {('ID: [' + id_num + ']').center(22)} |") print(f"| {('Phone: ' + phone).center(22)} |")
| Borchardt, Petros | | ID: [63 251283 B 185] | | Phone: 0419-0288803 |
Two ideas in one line: + glues strings together first (inside the parentheses), and only the finished sentence gets centered. Centering each piece separately would give you a completely different layout.
In class this was typed with double quotes inside a double-quoted f-string: f"| {(last_name + ", " + first_name)…}". That only runs on Python 3.12+. On 3.10 / 3.11 it is a SyntaxError. Use 'single' quotes inside a "double"-quoted f-string and it works everywhere.

Examine a product code 📦
