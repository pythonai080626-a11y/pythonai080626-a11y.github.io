01_comprehension.py

List Comprehension — One Line Instead of Four ✨

Here is a shape you wrote a dozen times last lesson: start empty, loop, append.

nums: list[int] = [3, 8, 15, 4, 23, 42, 7, 16] # the long way — 3 lines to say one thing squares = [] for n in nums: squares.append(n * n) print(squares)
[9, 64, 225, 16, 529, 1764, 49, 256]
The same thing, in one line
squares = [n * n for n in nums] print(squares)
[9, 64, 225, 16, 529, 1764, 49, 256]
Read it out loud, left to right: "n times n — for every n in nums". The square brackets around it are what make the answer a list. Everything you already know goes inside: the loop variable is yours to name, and the expression on the left can be anything.
[ n * n what to put in each cell for n in nums ]
PieceWhere it goesIn our example
the expressionfirst, before forn * n
the loopin the middlefor n in nums
the filter (optional)lastif n % 2 == 0
Adding a filter — keep only some of them
# only the even ones, unchanged evens = [n for n in nums if n % 2 == 0] print(evens) # doubled — but only the ones above 10 big_doubled = [n * 2 for n in nums if n > 10] print(big_doubled)
[8, 4, 42, 16] [30, 46, 84, 32]
The if at the end is a gate: a value that fails it never reaches the expression at all. That is why evens is shorter than nums — a comprehension with a filter gives you fewer items, one without a filter always gives you exactly as many.
A ternary inside — this one goes at the front
labels = ['big' if n > 10 else 'small' for n in nums] print(labels)
['small', 'small', 'big', 'small', 'big', 'big', 'small', 'big']
Two different ifs, two different places. An if at the end filters — it decides whether a value goes in. An if…else at the front is the ternary from lesson 11 — it decides which value goes in, and every item still gets a cell. If you write else at the end Python raises a SyntaxError.
filter — at the end, no else
[n for n in nums if n > 10]
[15, 23, 42, 16] ← 4 items
ternary — at the front, needs else
[n if n > 10 else 0 for n in nums]
[0, 0, 15, 0, 23, 42, 0, 16] ← 8 items
It works on strings too
names: list[str] = ['danny', 'moshe', 'suzi', 'sharon'] print([name.upper() for name in names]) print([len(name) for name in names]) print([name for name in names if 's' in name])
['DANNY', 'MOSHE', 'SUZI', 'SHARON'] [5, 5, 4, 6] ['moshe', 'suzi', 'sharon']
Every string method from lesson 12 is fair game inside a comprehension, and so is in from lesson 13. Notice the third line: 's' in name asks about the letters of one name, while the for … in names walks the list. Same word, two jobs — the position tells you which.
And it does not need a list to start from
print([i * i for i in range(1, 6)]) print([c for c in 'python']) print([int(x) for x in '20 5 13 7'.split()])
[1, 4, 9, 16, 25] ['p', 'y', 't', 'h', 'o', 'n'] [20, 5, 13, 7]
That last line is the single most useful comprehension there is: .split() hands you a list of strings, and the comprehension turns every one of them into an int. One line to read a whole row of numbers from the user.
A comprehension is for building a list. If you only want to print things, or to input() inside the loop, use a normal for — do not squeeze it into brackets just because you can.

02_any_all.py

all & any — Two Questions, No Loop 🔍

You have written this loop before. "Did everybody pass?"

grades: list[int] = [88, 91, 76, 95, 60] # the long way all_passed = True for g in grades: if g < 60: all_passed = False break print(all_passed)
True
Six lines become one
print(all(g >= 60 for g in grades)) # did EVERYBODY pass? print(any(g == 100 for g in grades)) # is there a perfect score? print(any(g > 90 for g in grades)) print(all(g > 90 for g in grades))
True False True False
WrittenReads asGives back
all(…)is it true for every single one?True / False
any(…)is it true for at least one?True / False
Both hand you a plain boolean, so they belong anywhere a comparison belongs — inside an if, inside a while, or stored in a well-named variable exactly like lesson 11 taught: everyone_passed = all(g >= 60 for g in grades) reads like English.
What is actually going inside the brackets

all and any do not take a condition — they take a list of True/False values. Which is exactly what a comprehension can build:

passed = [g >= 60 for g in grades] print(passed) print(all(passed)) print(any(passed)) # the version we actually write — same thing, without the middle list print(all(g >= 60 for g in grades))
[True, True, True, True, True] True True True
So all(g >= 60 for g in grades) is a comprehension with the square brackets dropped. Both spellings work and both are correct — all([g >= 60 for g in grades]) builds the whole list of booleans first, the version without brackets checks them one at a time and stops the moment it knows the answer. On a short list you will never notice; on a million items you would.
They also take a plain list of values
flags: list[bool] = [True, True, False] print(all(flags)) # False — one of them is not True print(any(flags)) # True — at least one is # careful: 0 and '' count as False print(all([5, 3, 9])) # True print(all([5, 0, 9])) # False — 0 is falsy
False True True False
The two edge cases worth memorising
ExpressionResultWhy
all([])Truenothing broke the rule — there was nothing to break it
any([])Falsenothing was true, because there was nothing at all
all([]) being True surprises everyone once. If your list can be empty and "empty" should not count as a pass, ask both: if len(grades) > 0 and all(g >= 60 for g in grades):.

The trap, and it is the same one as append. .sort() returns None. So scores = scores.sort() throws your entire list in the bin and leaves you holding None. Write scores.sort() on its own line, or use ordered = sorted(scores).

reverse — flip, do not sort

This is the one people mix up. .reverse() does not order anything. It turns the list back to front, exactly as it stands.

nums = [45, 12, 99, 3, 67] nums.reverse() print(nums) # flipped — and still not sorted! nums.sort(reverse=True) print(nums) # THIS is biggest-first
[67, 3, 99, 12, 45] [99, 67, 45, 12, 3]

Notice the pattern that runs through this whole lesson: the methods with a dot edit your list and return None; the functions build something new and leave the original alone. sort/sorted, reverse/[::-1] — same pair, twice. Once you see it, you never have to memorise which is which again.
Sorting compares items to each other, so they have to be comparable. [3, 'danny', True].sort() raises TypeError: '<' not supported between instances of 'str' and 'int'. One type per list — this is why it mattered.
03_sort.py

sort(key=…) — Your Rule, Not Python's 🔑

By default Python sorts numbers by size and words alphabetically. key= lets you say "no — sort them by this instead".

words: list[str] = ['banana', 'kiwi', 'apple', 'watermelon', 'fig'] words.sort() print(words) # alphabetical — the default words.sort(key=len) print(words) # shortest first words.sort(key=len, reverse=True) print(words) # longest first
['apple', 'banana', 'fig', 'kiwi', 'watermelon'] ['fig', 'kiwi', 'apple', 'banana', 'watermelon'] ['watermelon', 'banana', 'apple', 'kiwi', 'fig']
key=len — note there are no brackets after len. You are not calling it, you are handing the function itself to sort and saying "run this on every item, and sort by whatever comes out". len('fig') is 3, len('watermelon') is 10, so fig goes first.
key=len — what Python actually compares
fig3
kiwi4
apple5
banana6
watermelon10
Capital letters ruin alphabetical order
names = ['danny', 'Moshe', 'suzi', 'Sharon'] print(sorted(names)) # every capital jumps to the front print(sorted(names, key=str.lower)) # what a human expects
['Moshe', 'Sharon', 'danny', 'suzi'] ['danny', 'Moshe', 'Sharon', 'suzi']
Python sorts text by character code, and every uppercase letter comes before every lowercase one — so 'Sharon' lands before 'danny'. key=str.lower compares a lowercased copy of each name while leaving the names themselves untouched. This is the reason key= exists.
Sorting by distance from zero
temps = [-7, 3, -1, 12, -20] print(sorted(temps)) # coldest to hottest print(sorted(temps, key=abs)) # closest to zero first
[-20, -7, -1, 3, 12] [-1, 3, -7, 12, -20]
key=Sorts byTypical use
lenhow long each item iswords, names, lists inside a list
str.lowerthe lowercased textany list of names typed by a human
absdistance from zerotemperatures, errors, differences
intthe numeric value of a string['10', '9', '2'] — see below
nums_as_text = ['10', '9', '2', '33'] print(sorted(nums_as_text)) # '10' before '2' — they are TEXT print(sorted(nums_as_text, key=int)) # now it counts
['10', '2', '33', '9'] ['2', '9', '10', '33']
['10', '2'] sorted as text puts '10' first, because it compares character by character and '1' < '2'. If your numbers arrived from input() or .split() they are strings — either convert them with a comprehension, or sort with key=int.
A peek at what comes next. When no ready-made function fits, you write the rule yourself with lambda — a tiny one-line function:
words.sort(key=lambda w: w[-1]) # by LAST letter print(words)
['banana', 'apple', 'fig', 'kiwi', 'watermelon']
Read lambda w: w[-1] as "given a word w, the thing to sort by is w[-1]". You do not need it today — but when we reach functions, this line will already look familiar.
04_copy.py

b = a Does Not Copy a List 🧬

Everything up to lesson 13 behaved the obvious way. Two boxes, two values:

x = 5 y = x y = y + 1 print(x, y) # 5 6 — of course
5 6

Now the same two lines with a list. Look closely at what gets printed:

a: list[int] = [1, 2, 3] b = a # looks like a copy. it is not. b.append(4) print('a =', a) print('b =', b)
a = [1, 2, 3, 4] b = [1, 2, 3, 4]
We never touched a. And a changed. That is not a bug — b = a did not build a second list, it hung a second name on the one list that already existed.

Proving it — is vs ==
a = [1, 2, 3] b = a c = [1, 2, 3] # a different list that happens to look the same print(a == b) # True — same contents print(a is b) # True — literally the same list print(a == c) # True — same contents print(a is c) # False — two different lists
True True True False
OperatorAsksThink of it as

You already met is in lesson 10 as if x is None — same operator, same question. There is exactly one None in all of Python, so asking "is it the None" is the right question there.
A real copy — three ways, all identical
a = [1, 2, 3] b = a.copy() # the clearest — say what you mean b = a[:] # a slice of everything is a new list b = list(a) # build a new list out of a b.append(4) print('a =', a) print('b =', b) print(a is b)

a[:] is a slice with no start and no end — "everything" — and every slice builds a new list. That is why it copies. a.copy() does the same thing and says so out loud; prefer it.
Where this bites you for real. You want to sort a list without losing the original order, so you write backup = grades and then grades.sort() — and discover backup is sorted too, because there was only ever one list. The fix is one word: backup = grades.copy(). Or skip the copy entirely and use sorted(grades), which never touched the original in the first place.

.clear() — and Why Not Just = [] 🧹

You want to empty a list. There are two ways to write it, they print the same thing, and they are not the same thing at all.

a.clear() — empties the list
a = [1, 2, 3] b = a a.clear() print(a) print(b)
[] [] ← b sees it too
a = [] — moves the name
a = [1, 2, 3] b = a a = [] print(a) print(b)
[] [1, 2, 3] ← nothing was emptied
Say what each line actually does.
a.clear() reaches into the list and throws out its contents. Everyone pointing at that list — a, b, whoever else — now sees an empty list, because there is one list and it is empty.
a = [] never touches the old list at all. It builds a brand new empty list and re-points the name a at it. The old list is still there, still full, and b is still holding it.
The same picture, twice

Where = [] silently does nothing

Two names is the easy case. Here is the one that costs people an afternoon — a list living inside another list:

clear works
board = [[1, 2], [3, 4]] row = board[0] row.clear() print(board)
[[], [3, 4]]
= [] does nothing
board = [[1, 2], [3, 4]] row = board[0] row = [] print(board)
[[1, 2], [3, 4]] ← unchanged
row was a second name for the list sitting in board[0]. row.clear() emptied that list, and board saw it immediately. row = [] just pointed the local name row somewhere else and left board completely untouched. The same thing happens with a list handed into a function — which is the next lesson's problem, and the reason this matters.
When each one is the right call

Reach for it when…the list is shared, or lives inside somethingit is a private local list and you are starting fresh
There is a smaller, quieter reason too. Inside a loop that empties a list every round, lst = [] creates a brand new list on every single pass and leaves the old one for the garbage collector. lst.clear() keeps reusing the one object. It rarely matters on ten items — it does on ten million.
Rule of thumb: if anyone else can see the list, use .clear(). If the list is entirely yours and nobody else knows about it, = [] is fine — and honestly a little clearer to read.

The price list 🏷️

A shop keeps its prices in one list:

prices: list[int] = [120, 45, 300, 89, 210, 15, 74]

Using a comprehension for every single one — no append, no empty list to start from:

  1. Build doubled — every price times 2. Print it.
  2. Build expensive — only the prices above 100. Print it.
  3. Build on_sale — the prices above 100, with 50 off each. (Expression and filter, in one comprehension.) Print it.
  4. Build labels — the word 'pricey' for a price above 100 and 'cheap' otherwise, one label per price. Print it.
  5. Build as_text — every price as a string with its currency, like '120 NIS'. Print it.
Expected output
Doubled: [240, 90, 600, 178, 420, 30, 148] Expensive: [120, 300, 210] On sale: [70, 250, 160] Labels: ['pricey', 'cheap', 'pricey', 'cheap', 'pricey', 'cheap', 'cheap'] As text: ['120 NIS', '45 NIS', '300 NIS', '89 NIS', '210 NIS', '15 NIS', '74 NIS']
Hint — steps 2 and 4 look similar and are not. Step 2 is a filter: the if goes at the end, there is no else, and you get 3 items back. Step 4 is a ternary: the if…else goes at the front, and you get all 7 back. Count the items in the expected output — that is how you check yourself.
# filter — fewer items come out [p for p in prices if p > 100] # ternary — same number of items, different values ['…' if p > 100 else '…' for p in prices]
Hint — step 5 wants an f-string. Straight from lesson 12, just living inside brackets now: [f'{p} NIS' for p in prices].

The battery report 🔋

A warehouse scanned the battery level of six devices:

battery: list[int] = [78, 92, 45, 61, 88, 30]

Answer each of these and print the answer:

  1. Is every device above 20%? Use all.
  2. Is at least one device below 40%? Use any.
  3. Is every device fully charged (100)? Use all.
  4. Build ordered — the levels sorted lowest first, without changing battery. Print ordered and then print battery to prove it survived.
  5. Now sort battery itself, highest first, in place. Print it.
  6. Print the top three levels — one slice off the list you just sorted.
Expected output
All above 20: True Any below 40: True All full: False Ordered: [30, 45, 61, 78, 88, 92] Original: [78, 92, 45, 61, 88, 30] Sorted desc: [92, 88, 78, 61, 45, 30] Top three: [92, 88, 78]
Hint — step 4 is the whole point of the question. If you write battery.sort() there, the "Original" line will come out sorted and you will have lost the answer. One of sort / sorted leaves the list alone — pick that one.
Check yourself: if the Original: line does not print [78, 92, 45, 61, 88, 30] exactly as it was written, you used the in-place version too early. And if any line prints None, you wrote battery = battery.sort() — drop the battery =.

  6. הדפיסו את שלוש הרמות הגבוהות — חיתוך אחד על הרשימה שזה עתה מיינתם.

רמז — סעיף 4 הוא כל העניין של השאלה. אם תכתבו שם battery.sort(), השורה של Original תצא ממוינת ואיבדתם את התשובה. אחד מבין sort / sorted לא נוגע ברשימה — בחרו בו.

צור את הרשימה הבאה:

words = ["HELLO", "WORLD", "PYTHON", "CODE", "DEVELOPER", "AI"]

בצע את הבדיקות הבאות:

  1. בדוק אם כל המילים כתובות באותיות גדולות בלבד
    השתמש ב־all
  2. בדוק אם קיימת לפחות מילה אחת עם יותר מ־5 תווים
    השתמש ב־any
  3. בונוס: הדפיסו את המילים ממוינות לפי אורך, מהקצרה לארוכה, בלי לשנות את words. השתמשו ב-sorted עם key=.

רמז — מתודות המחרוזות משיעור 12 עדיין כאן. 'HELLO'.isupper() כבר עונה על שאלה 1 עבור מילה אחת; all שואל אותה על כל השש בבת אחת. ו-len(w) > 5 הוא התנאי לשאלה 2 — ל-'PYTHON' יש בדיוק 6 אותיות, ולכן התשובה היא True.
