03_dict.py

A for Loop Can Open the Box 📦

The file opens with a line that looks strange until you see what it does:

l1 = [{1, 2}, [3, 4], (5, 6)] for x, y in l1: print('x=', x, 'y=', y)
x= 1 y= 2 x= 3 y= 4 x= 5 y= 6

A list of three items — a set, a list and a tuple. Every one of them holds exactly two things, so instead of writing for item in l1 and then digging out item[0] and item[1], you write two names in the for line and Python hands you both at once. That is unpacking.

for item in l1: x = item[0] y = item[1]
→
for x, y in l1:
The number of names must match the number of items. If one entry held three things, for x, y in l1 would raise ValueError: too many values to unpack. And a set has no order — {1, 2} only came out as x=1 y=2 because of how these particular small numbers happen to be stored. Never rely on it.

Remember this shape, because the very next thing in the file is a dictionary handing you exactly such pairs.

.items() — Looping Both Halves at Once 🔑

stock = {'apple': 5, 'banana': 2, 'cherry': 9} print(stock.items()) for key, value in stock.items(): print('key=', key, 'value=', value)
dict_items([('apple', 5), ('banana', 2), ('cherry', 9)]) key= apple value= 5 key= banana value= 2 key= cherry value= 9

Look at the first printed line, before the loop. .items() hands back something that behaves like a list of two-item tuples — ('apple', 5), ('banana', 2)… which is exactly the shape you just learned to unpack. That is the whole trick: .items() makes the pairs, and for key, value in opens each one.

stock.items()
'apple'→5
'banana'→2
'cherry'→9

Three ways to walk a dict, and it is worth knowing which one you want:

LoopYou get
for k in stock:the keys only (same as .keys())
for v in stock.values():the values only — no way back to the key
for k, v in stock.items():both — this is the one you will use most

Taking a Pair Out — pop · popitem · del 🗑️

d = {'a': 1, 'b': 2, 'c': 3, 'd': 4} # pop returns the VALUE it removed val = d.pop('b') print(val) # → 2 # Missing key → KeyError, unless you give a default safe = d.pop('zzz', 'not here') print(safe) # → not here # popitem removes the LAST inserted pair pair = d.popitem() # → ('d', 4) a tuple print(d) # → {'a': 1, 'c': 3}
WayWhat it removesWhat you get back
del d['b']the pair you namenothing — it is a statement, not a method
d.pop('b')the pair you namethe value → 2
d.pop('zzz', 'not here')nothing — the key is absentyour default, instead of a crash

The second argument to .pop() is the same safety net as the second argument to .get() from last lesson. The difference between them: .get() looks, .pop() takes. Both refuse to crash when you hand them a fallback.
popitem() takes no arguments — you do not choose which pair goes, you get the most recently added one. On an empty dict it raises KeyError: 'popitem(): dictionary is empty'.
03_dict.py

setdefault — Only If It Is Not There Yet 🪄

d = {'dana': '19:30:00'} d.setdefault('dana', 'not here yet') # dana already exists → nothing changes # 1 d.setdefault('omer', 'not here yet') # omer is new → gets added # 2 same if 'omer' not in d.keys(): d['omer'] = 'not here yet' print(d)
{'dana': '19:30:00', 'omer': 'not here yet'}

Dana signed in at 19:30, so her value is left alone. Omer has no entry, so he gets the placeholder. The two blocks marked # 1 and # 2 in the file do the same thing — the second one spells out in three lines what the first does in one.

setdefault
d.setdefault(k, v)

Adds k only if it is missing. Either way it returns the value that is now under k.

plain assignment
d[k] = v

Always writes — and overwrites whatever was already there. Dana's 19:30 would be gone.

Keep the pair straight: .get(k, default) reads without touching the dict; .setdefault(k, default) reads and writes the default in when the key is missing.

Copy, Alias, Clear — The Trap ⚠️

d = {'a': 1, 'b': 2, 'c': 3} # del removes a key (returns nothing) del d['b'] # .copy() → an independent shallow copy clone = d.copy() clone['a'] = 99 # d['a'] is still 1 # ⚠️ clone = d does NOT copy — same object! alias = d alias['a'] = 0 # d changed too # .clear() empties it in place clone.clear() # → {}

This is the most expensive misunderstanding in the language, so look at the drawing rather than the words. = does not make a new dict. It writes a second name on the same box:

Two names on one dict, versus two real dicts.
Shallow copy means the top level is new, but the values are shared. If a value is itself a list or a dict, both copies still point at that same inner object. For a fully independent copy there is copy.deepcopy() — a later lesson.

.clear() empties a dict in place, keeping the same box. That matters: every name pointing at that dict now sees {}.

03_dict.py

in Asks About Keys 🔍

d = {'a': 10, 'b': 20, 'c': 30} # `in` checks KEYS — O(1), no searching print('a' in d) # → True (same as 'a' in d.keys()) print(10 in d) # → False (10 is a value, not a key) print(10 in d.values()) # → True # len() = number of pairs print(len(d)) # → 3 # Looping a dict loops its KEYS for k in d: # same as: for k in d.keys() print(k, d[k])
True False True 3 a 10 b 20 c 30

Three facts worth memorising, because they decide how your programs get written:

  • in means "is this a key" — never a value. To ask about values you must say in d.values(), and that one really does search item by item.
  • Key lookup is O(1) — the same hashing you met with sets. A dict with a million pairs answers 'a' in d just as fast as one with three.
  • A bare loop gives keys, and from a key you can always reach the value with d[k]. That is why both for k in d: and for k, v in d.items(): are fine — .items() just saves you the extra lookup.

Merging Two Dicts with | ➕

a = {'x': 1, 'y': 2} b = {'y': 99, 'z': 3} # | makes a NEW dict (Python 3.9+) merged = a | b # → {'x': 1, 'y': 99, 'z': 3} b wins on 'y' # |= merges INTO a (like a.update(b)) a |= b # Works in every version: unpacking # merged2 = {**a, **b}
{'x': 1, 'y': 2}
|
{'y': 99, 'z': 3}
→
{'x': 1, 'y': 99, 'z': 3}

You met | last lesson as set union. On dicts it means the same thing — everything from both sides — plus one rule sets never needed: when the same key appears on both sides, the right-hand dict wins. That is why 'y' came out 99 and not 2.

Who Got the Highest Score? 🏆

scores = {'dana': 88, 'ben': 95, 'ada': 72} print(max(scores, key=scores.get)) # → ben the KEY print(scores.get(max(scores, key=scores.get))) # → 95 its value print(max(scores.values())) # → 95 the value alone print(max([6, 90, 200, -1])) # → 200 plain old max k, v = max(scores, key=scores.get), max(scores.values()) print('k, v', k, v) # → k, v ben 95

Start with the line you already understand: max([6, 90, 200, -1]) is 200. max looks at every item and keeps the biggest. Now hand it a dict — and a dict, looped plainly, gives its keys. So max(scores) would compare the strings 'dana', 'ben', 'ada' alphabetically and answer 'dana'. Not what anybody wanted.

The key= argument changes what gets compared

key=scores.get says: for every candidate, do not compare it directly — first run it through scores.get and compare that instead. The candidates are still the names, so the answer is a name — but the comparison happens on the numbers.

Judged on the values, returned as the key.
Write scores.get with no parentheses. You are handing max the method itself, so that it can call it once per candidate. scores.get() would call it right now, with no key, and fail.
Sorting a dict — two one-liners
print({k: scores[k] for k in sorted(scores)}) # → {'ada': 72, 'ben': 95, 'dana': 88} by key, A-Z print({k: scores[k] for k in sorted(scores, key=scores.get)}) # → {'ada': 72, 'dana': 88, 'ben': 95} by value, low → high

The same key= idea, now on sorted instead of max, wrapped in a dict comprehension so the result is a dict again and not a list of names. There is a shorter version in the file, commented out for a later lesson:

# print('1 liner', max(scores.items(), key=lambda x: x[1]))

04_dict.py

The Counting Pattern 🔢

This is what dictionaries get used for more than anything else. The task, written at the top of the file:

text = 'missiiiissippi' # {'m': 1, 'i': 4, 's': 4, 'p': 2} d = {} # 1 fill dict like in the example # 2 use max to find the letter which appears the most

Think about what you need for each letter, one at a time. Have I seen this one before? If no — start it at 1. If yes — take what is there and add one:

for c in text: print(c, end=" ") # does c appear in dict-keys? # no - add c: 1 # yes - store the value + 1 if c not in d: d[c] = 1 else: d[c] += 1 # or # d[c] = d.get(c, 0) + 1 print() print(d) print(f"max= '{max(d, key=d.get)}', {d[max(d, key=d.get)]} times")
m i s s i i i i s s i p p i {'m': 1, 'i': 7, 's': 4, 'p': 2} max= 'i', 7 times
The one-line version

The commented line in the file replaces the whole if/else:

if c not in d: d[c] = 1 else: d[c] += 1
→
d[c] = d.get(c, 0) + 1

Read it from the inside out. d.get(c, 0) is "the count so far, or zero if this letter is new". Add one. Store it back. The first time round that is 0 + 1; every time after, it is the real count plus one. The 0 default does the entire job of the if.

print(c, end=" ") — end= replaces the newline that print normally adds, so the letters come out on one line as the loop walks them. It is only there to let you watch the loop; delete it and nothing about the counting changes.

defaultdict — Missing Keys That Build Themselves 🏗️

from collections import defaultdict text = 'mississippi' d = defaultdict(int) for c in text: print(c, end=" ") d[c] = d[c] + 1 print() print(d) print(f"max= '{max(d, key=d.get)}', {d[max(d, key=d.get)]} times")
m i s s i s s i p p i defaultdict(<class 'int'>, {'m': 1, 'i': 4, 's': 4, 'p': 2}) max= 'i', 4 times

Look at the loop body: d[c] = d[c] + 1 — no if, no .get(). On a normal dict the very first letter would blow up with KeyError, because you are reading d['m'] before anything was ever written there.

What defaultdict(int) promises

"If somebody asks for a key I do not have, do not raise — call int(), store the result under that key, and hand it back." And int() with no arguments is 0. So the first d['m'] quietly becomes 0, and + 1 makes it 1.

d = {} d['m'] + 1 → KeyError
vs
d = defaultdict(int) d['m'] + 1 → 1
You writeA missing key becomesGood for
defaultdict(int)0counting
defaultdict(list)[]grouping — d[k].append(x)
defaultdict(str)''building up text
Two things to keep in mind. It prints as defaultdict(<class 'int'>, {...}) and not as a plain dict — wrap it in dict(d) if you want the clean look. And merely reading a missing key creates it, so a stray d['zzz'] silently adds 'zzz': 0 to your data.
from collections import defaultdict — collections ships with Python, there is nothing to install. Same shape as import random from lesson 8, except here you pull one name out of the module instead of taking the whole module.
05_func.py

def — Giving a Block of Code a Name 🏷️

Everything you have written so far runs once, top to bottom. If you needed the same five lines in two places, you copied them. The file opens by sketching the idea in comments:

# functions # <name> # 1 # 2 # 3 # ... # <name> # # # <name>

A name, and underneath it the indented lines that belong to it. That block does not run when Python reads it — it just gets stored under that name, waiting. It runs when you call it, and it runs again every time you call it again.

Defining stores the block. Calling runs it.

Here is the real function from the file, with the two parts labelled:

def my_first_function(): # ← the def line, ends with a colon ''' my first function this is a demo function :return: ''' global x x += 1 print("Hello World") # ← the body, indented print(x) goodbye() # ← a function calling another function my_first_function() # ← the call, back at the left margin
PartRule
defthe keyword that starts a definition
my_first_functionthe name — lowercase with underscores, like a variable
()where parameters would go; empty here — this one takes nothing
:ends the def line, exactly like if and for
indented blockthe body — everything indented belongs to the function
my_first_function()the call. Without the () you are only naming it, not running it

05_func.py

Define Before You Call ⛔

The first real line of the file is commented out on purpose:

########## # goodbye() # Error x = 1

Uncomment it and you get:

NameError: name 'goodbye' is not defined

Python reads the file from the top down. At that point it has not reached the def goodbye(): line yet, so the name simply does not exist. A function must be defined before the line that calls it runs.

But look at what the file gets away with
def my_first_function(): ... goodbye() # goodbye is not defined yet — and this is fine! def goodbye(): ... # my_first_function() my_first_function() # by NOW, both names exist

Inside my_first_function there is a call to goodbye, written above the def goodbye. No error. The reason is the rule from the previous panel: the body of a function does not run when it is defined. Python only reads it. By the time my_first_function() is actually called on the last lines, def goodbye has long since been read, so the name is there.

goodbye() def goodbye(): ...
NameError
def a(): b() def b(): ... a()
✓ works
Reading the output in order
my_first_function() print('-- finished') print(3)
Hello World 2 goodbye 3 -- finished 3

Follow it line by line, because the order surprises people. my_first_function() prints Hello World and 2, then calls goodbye(), which prints goodbye and 3. Only when goodbye has completely finished does control come back to where it was, and only then does -- finished appear.

Notice the commented # my_first_function() inside goodbye. Uncomment it and the two functions call each other forever, until Python stops you with RecursionError: maximum recursion depth exceeded. It is left in the file as a warning, not as a suggestion.
05_func.py

global — Reaching Outside the Function 🌍

x = 1 def my_first_function(): global x x += 1 print("Hello World") print(x) # → 2 goodbye() def goodbye(): global x x += 1 print("goodbye") print(x) # → 3

A variable born inside a function is local: it exists while the function runs and disappears the moment it ends. Reading an outside variable is allowed anyway — but the second you assign to a name, Python decides that name is local, and x += 1 is an assignment. Without the global line you would get:

UnboundLocalError: cannot access local variable 'x' where it is not associated with a value

global x is the promise: when I say x in here, I mean the x outside — do not make me a new one. That is why the count keeps climbing across the two functions: 1 at the top of the file, 2 in the first function, 3 in the second.

x = 11
first function2
goodbye3
Use it sparingly. global is shown here so you understand what scope is, not because it is good style. When any function anywhere can rewrite a variable, a bug becomes very hard to trace. The clean way is coming next lesson: hand values in as parameters and hand the answer out with return.

05_func.py

Docstrings and help() 📄

def my_first_function(): ''' my first function this is a demo function :return: ''' ...

The triple-quoted string on the first line of the body is a docstring. It is not a comment: a comment is thrown away, this one gets attached to the function and travels with it. Anyone can read it back without opening your file:

help(my_first_function)
Help on function my_first_function in module __main__: my_first_function() my first function this is a demo function :return:
help(my_first_function) — no parentheses on the inner name. help(my_first_function()) would call your function first and then ask for help on whatever it returned.

Try the same thing on functions you already use — help(print), help(dict.get), help(max). Every one of them answers, because the people who wrote them left a docstring too.

:return: is PyCharm's template. Type ''' under a def line and press Enter — the editor writes the skeleton for you, with a :param: line for every parameter. Fill it in; the empty :return: in this file is just what the template left behind.

Exercise — Is It a Power of 2? ⚡

The user types a number. Your program answers yes, and which power — or no.

enter a number: 32 yes 2 power 5 enter a number: 100 no
The two rules that make this an exercise:
  1. Use a dict. The answer must come out of a dict — that is what today's lesson was about. Not a list, not an if chain.
  2. No calculating after the input(). No **, no dividing by 2 in a loop, no log. Every calculation happens before the user types. All that is left afterwards is one dict lookup.
  1. Build the dict before the input Loop the exponents you want to support and fill a dict — one pair per power of two. This is the only place any arithmetic is allowed:
    powers = {} for i in range(33): powers[?] = ?
  2. Decide which way round the pair goes 🔑 This is the whole exercise. You will be handed 32 and asked for 5 — so 32 has to be the key and 5 the value. Build it the other way round and you are back to searching.
    powers — number → exponent
    1→0
    2→1
    4→2
    8→3
    16→4
    32→5
    …→…
  3. Ask the user input() always hands back a string, and '32' is not the same key as 32. Convert it with int() or nothing will ever be found.
  4. One lookup in the dict, then print Two tools from today do this, and both are a single line: in to ask whether the key is in the dict, or .get() with a default. Print yes 2 power 5 or no.
    Careful with .get(): for 1 the exponent is 0, and 0 is falsy — so if p: would wrongly answer no for the number 1. Ask if p is not None:, or use in.
  5. ⭐ Bonus — powers of 2, 3 and 5 Build three dicts before the input — one for the powers of 2, one for 3, one for 5 — and check the number the user typed against all three. The rules do not change: everything is built up front, and after the input() there are only lookups.
    powers2 = {} powers3 = {} powers5 = {} # fill all three here, before the input
    enter a number: 32 yes 2 power 5 enter a number: 81 yes 3 power 4 enter a number: 125 yes 5 power 3 enter a number: 100 no
    Try 1 — it is 2**0, 3**0 and 5**0, so all three dicts have it. Decide what your program should say, and make sure it does not stop at the first match if you want all of them.
    The tidier way, once it works: instead of three separate names, keep one dict whose values are dicts — tables = {2: {…}, 3: {…}, 5: {…}} — and walk it with for base, table in tables.items():. Same two things from today: a nested dict, and .items(). Adding base 7 is then one line, not four.
    If you want the program to keep going, wrap the question in a while True that stops on q — with the dicts built once, before the loop, never inside it.
Why this is worth doing: the slow version divides by 2 over and over after every input. Yours does the work once, up front, and then answers any number in a single O(1) hash lookup — no matter how many numbers the user throws at it. That is the entire reason dictionaries exist.

שיעורי בית — האם זו חזקה של 2? ⚡

המשתמש מקליד מספר. התוכנית עונה כן, ואיזו חזקה — או לא.

enter a number: 32 yes 2 power 5 enter a number: 100 no
שני החוקים שהופכים את זה לתרגיל:
  1. חובה להשתמש במילון. התשובה חייבת לצאת מתוך dict — זה מה שלמדנו היום. לא רשימה, ולא שרשרת if.
  2. אסור לחשב אחרי ה-input(). בלי **, בלי חילוק ב-2 בלולאה ובלי log. כל החישובים נעשים לפני שהמשתמש מקליד. מה שנשאר אחר כך הוא חיפוש אחד במילון.

זה כל התרגיל. אתם תקבלו את 32 ותצטרכו להחזיר 5 — ולכן 32 חייב להיות המפתח ו-5 הערך. אם תבנו הפוך, תחזרו לחפש.

4 · חיפוש אחד במילון, ואז הדפסה 🎯

שני כלים מהשיעור עושים בדיוק את זה, ושניהם שורה אחת: in ששואל אם המפתח נמצא במילון, או .get() עם ברירת מחדל. הדפיסו yes 2 power 5 או no.

5 · ⭐ בונוס — חזקות של 2, 3 ו-5

בנו שלושה מילונים לפני הקלט — אחד לחזקות של 2, אחד ל-3 ואחד ל-5 — ובדקו את המספר שהמשתמש הקליד מול שלושתם. החוקים לא משתנים: הכול נבנה מראש, ואחרי ה-input() יש רק חיפושים.

powers2 = {} powers3 = {} powers5 = {} # fill all three here, before the input
enter a number: 32 yes 2 power 5 enter a number: 81 yes 3 power 4 enter a number: 125 yes 5 power 3 enter a number: 100 no
נסו את 1 — הוא 2**0, 3**0 וגם 5**0, כלומר הוא נמצא בשלושת המילונים. תחליטו מה התוכנית שלכם אמורה להגיד, ואל תעצרו בהתאמה הראשונה אם אתם רוצים את כולן.
הדרך המסודרת, אחרי שזה עובד: במקום שלושה שמות נפרדים, החזיקו מילון אחד שהערכים שלו הם מילונים — tables = {2: {…}, 3: {…}, 5: {…}} — ועברו עליו עם for base, table in tables.items():. בדיוק שני הדברים מהיום: מילון מקונן ו-.items(). להוסיף בסיס 7 זו אז שורה אחת במקום ארבע.
אם תרצו שהתוכנית תמשיך לשאול, עטפו את השאלה ב-while True שנעצר על q — כשהמילונים נבנים פעם אחת, לפני הלולאה, אף פעם לא בתוכה.
