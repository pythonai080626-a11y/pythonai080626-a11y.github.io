Dictionaries — Look It Up By Name 📖

A list finds things by position: person[0], person[1], person[2] — and you have to remember what lives at each number. Today's type finds things by name: person['age']. Every entry is a pair, a key and a value, and the key is whatever makes sense to you. It keeps the instant lookup you met last lesson (a dict is a set that carries a value along with each item), it keeps insertion order, and the value can be anything — a number, a list, another dict. This is the type real programs are actually made of.

Reaching in — one bracket per step down
print('number of kids=', len(person['kids age'])) print('first name=', person['first name']) print('house number', person['address']['house_number']) print('city', person['address']['city']) print('Hobbies', person['Hobbies'][-1])

Read person['address']['house_number'] left to right, one bracket at a time. person['address'] hands you back a dict — so the next ['house_number'] is asked of that dict. Same story with person['Hobbies'][-1]: the first bracket gives a list, so the second bracket is a list index, and -1 means the last one. The brackets change meaning depending on what came back.
The strange key: frozenset('Gender')
print('Gender', person[frozenset('Gender')])
Gender F
Nobody writes keys like this in real code — it is in the file to prove a point. Remember from lesson 15 that frozenset('Gender') breaks the string into characters and drops the duplicate e, giving frozenset({'G','e','n','d','r'}). A frozenset is immutable, so Python accepts it as a key. To read the value back you must build the exact same frozenset again — which is why the plain string person['Gender'] would raise KeyError.
Printing the whole thing — pprint
from pprint import pprint print(person) # one very long line pprint(person) # "pretty print" — one pair per line
pprint is a standard module. Same content, laid out so a human can read it. Handy the moment a dict stops fitting on one line.

The Rules Live on the Key Side 🔑

Rule 1 — an empty {} is a dict, not a set
# An empty dict — {} IS a dict (not a set!) empty = {} print(type(empty))
<class 'dict'>
Last lesson this was the annoying detail: the empty set has to be set() because {} was already taken. Now you can see who took it. The dict got the braces first.
Rule 2 — a key appears once, the last one wins
d = {'a': 1, 'a': 2} print(d) d['a'] = 3 print(d)
{'a': 2} {'a': 3}
No error, no warning — 1 is quietly thrown away. It is the same rule as a set: keys are unique. Writing to a key that already exists does not add a second entry, it replaces the value.
Rule 3 — the key must be hashable
str  ✓ int  ✓ tuple  ✓ frozenset  ✓ list  ✗ set  ✗ dict  ✗
d = {[1, 2]: 'oops'} # ← a list as a key
TypeError: unhashable type: 'list'
Exactly the rule you met with sets, and for exactly the same reason: Python locates a key by calculating a number from it. If the value could change afterwards the number would go stale and the entry would be lost. So anything that can change is refused. Values have no such rule — a list is a perfectly good value, just not a key.

Four More Ways to Build One 🏗️

1 · dict() with keyword arguments
a = dict(name='Dana', age=17) # → {'name': 'Dana', 'age': 17}
Notice there are no quotes around name and age here — they are written like variable names, and Python turns them into strings for you. Convenient, but it only works for keys that are legal names: dict(first name='danny') is a syntax error, while {'first name': 'danny'} is fine.
2 · dict() from a list of pairs
b = dict([ ('x', 1), ('y', 2) ]) # → {'x': 1, 'y': 2}
Each little tuple is one row: first item becomes the key, second becomes the value.
3 · zip() — back to the two parallel lists
a = ['red', 'green', 'blue', 'white'] b = ['#f00', '#0f0', '#00f'] colors = dict(zip(a, b)) print(colors)
{'red': '#f00', 'green': '#0f0', 'blue': '#00f'}
Count them: four colour names went in, only three came out. zip pairs up items one by one and stops the moment the shorter list runs out — 'white' has no partner, so it is silently dropped. No error. If your dict ever comes out shorter than you expected, this is the first thing to check.
zip pairs until one side runs out — the leftovers vanish without a word.
4 · A dict comprehension
animals = ['cat', 'horse', 'ox'] dict_animals = {animal: len(animal) for animal in animals} print(dict_animals)
{'cat': 3, 'horse': 5, 'ox': 2}
The same shape you already used for lists and sets — the only new part is the : between the key and the value. {animal for ...} would build a set; {animal: len(animal) for ...} builds a dict. One colon, different type.
5 · dict.fromkeys() — same starting value for everyone
# Same starting value for every key scores = dict.fromkeys(['a', 'b', 'c'], 0) # → {'a': 0, 'b': 0, 'c': 0} blank_person = dict.fromkeys(person.keys(), None) print(blank_person)
{'first name': None, 'last name': None, 'age': None, 'address': None, 'kids age': None, 'Hobbies': None, 'cars': None, frozenset({'G', 'r', 'n', 'd', 'e'}): None, 'Vegan': None}
A nice trick in that second line: take the keys of an existing dict and build an empty form with the same fields, every value None waiting to be filled. That is exactly the shape of the attributes dict in today's exercise.

.get() takes an optional second argument: what to hand back if the key is not there. With no second argument you get None. Keys, Values, and Both Together 📋

stock = {'apple': 5, 'banana': 2, 'cherry': 9} print(stock.keys()) print(list(stock.keys())) print(stock.values())
dict_keys(['apple', 'banana', 'cherry']) ['apple', 'banana', 'cherry'] dict_values([5, 2, 9])
dict_keys([...]) looks odd but it is not a list — it is a view, a live window onto the dict. You can loop it and use in on it. Wrap it in list(...) when you actually need a list you can index or sort. And because it is live, adding a key to stock makes it appear in a view you took earlier.
Looping — and .items(), the useful one
for fruit in stock: # looping a dict gives KEYS print(fruit, stock[fruit]) for fruit, qty in stock.items(): # both halves at once print(fruit, '→', qty)
apple 5 banana 2 cherry 9 apple → 5 banana → 2 cherry → 9
for x in stock walks the keys, not the values, and not the pairs. If you want both, .items() hands you two variables per turn. And 'apple' in stock asks about keys too — 5 in stock is False even though 5 is sitting right there as a value. For values you must say 5 in stock.values().

Upsert — One Line That Does Two Jobs ✍️

d = {'name': 'Dana', 'age': 17} # upsert -- insert + update d['city'] = 'Haifa' # if 'city' not exist - create, else: overwrite d['name'] = 'moshe' # if 'name' not exist - create, else: overwrite print(d)
{'name': 'moshe', 'age': 17, 'city': 'Haifa'}
upsert = update + insert. Python does not make you choose. The very same line adds 'city' (it was not there) and replaces 'name' (it was). Compare with a list, where adding uses .append() and replacing uses lst[i] = ... — and where lst[99] = 'x' on a short list is an IndexError. A dict has no such problem: there is no "out of range" for a name.
Look at the print order too: 'city' came last because it was added last, while 'name' stayed in first position — overwriting a value does not move the key. A dict remembers the order you inserted keys in.
Many at once — .update()
d.update({'age': 19, 'grade': 12}) print(d)
{'name': 'moshe', 'age': 19, 'city': 'Haifa', 'grade': 12}
.update() is just upsert applied to every pair you hand it: 'age' existed so it was overwritten (17 → 19), 'grade' did not so it was added at the end.

Build a D&D Character 🎲

In Dungeons & Dragons every character is a sheet of paper: a name, six numbers that say what they are good at, and a bag of things they carry. That sheet is a dictionary. Here is the one we are going to fill in — it comes ready-made at the bottom of 02_dict.py:

items_options = {'sword', 'shield', 'staff', 'mace', 'ring', 'boots'} item_icons_set = {'⚔️', '🛡️', '🪄', '🔨', '💍', '🥾'} attributes = { 'name': None, 'strength': 15, 'dexterity': 12, 'constitution': 14, 'intelligence': 10, 'wisdom': 13, 'charisma': 8, 'inventory': [] }

Your mission — create a character:
  1. Get the character name — input() from the user.
  2. Put the name into the 'name' value (key = name, value = user input).
  3. Each stat is between 3 and 18 — random values for all six attributes.
  4. Put 2 random items in the inventory.
  5. Bonus: ask the user to accept or roll again — the name stays the same.
Why 3 to 18? 🎲🎲🎲
In the real game you roll three six-sided dice, so a stat can never be below 3 or above 18. We get the same range in one line: random.randint(3, 18).
The one thing to think about before you start
Look again at the two collections you were given. items_options and item_icons_set are both sets — and a set has no order. So there is no way to say "the third icon belongs to the third item". If you want 'sword' to reliably show ⚔️, you need a structure that keeps pairs together… which is exactly the type you learned today. Turn the icons into a dict.
Everything you need is on the shelf: input(), random.randint(a, b), random.sample(seq, k), d[key] = value, and a for loop over the stat names. Try it yourself before opening the next panel.
Solution

Solving It, Step by Step ✅

  1. Fix the icons — a set cannot pair anything

    Replace the icon set with a dict. Now every item name carries its own picture, and the order stops mattering:

    item_icons = {'sword': '⚔️', 'shield': '🛡️', 'staff': '🪄', 'mace': '🔨', 'ring': '💍', 'boots': '🥾'} print(item_icons['sword']) # ⚔️ — always the right one
  2. Ask for the name and upsert it
    name = input('What is your character name? ') attributes['name'] = name # the key exists (None) → overwritten
  3. Roll the six stats

    We do not want to write six almost-identical lines. Keep the six names in a list and loop — each turn the loop variable becomes the key:

    import random stat_names = ['strength', 'dexterity', 'constitution', 'intelligence', 'wisdom', 'charisma'] for stat in stat_names: attributes[stat] = random.randint(3, 18) # 3 and 18 both included
    attributes[stat] — the key is a variable, not a fixed string. First time round the loop it means attributes['strength'], next time attributes['dexterity'], and so on. This is the move that makes dicts powerful.
  4. Pick 2 random items — without picking the same one twice
    attributes['inventory'] = random.sample(list(items_options), 2)
    Two traps in that one line. (a) random.choice twice could hand you the sword twice — random.sample picks two different ones. (b) random.sample wants a sequence, something with an order it can index into — and a set has none. On Python 3.11 and newer, handing it a set is an outright error:
    TypeError: Population must be a sequence
    On 3.9 / 3.10 it still limps along but prints DeprecationWarning: Sampling from a set deprecated. Either way, wrap it: list(items_options).
  5. Print the sheet
    print('name:', attributes['name']) for stat in stat_names: print(stat, '=', attributes[stat]) for item in attributes['inventory']: print(item, item_icons[item]) # name + its icon
The whole thing together

Your Report Card 📊

One dictionary holds your whole report card: the key is the subject, the value is the grade.

grades
'math'→90
'english'→78
'literature'→65
'python'→100
1

Ask the user for four grades

Start with an empty dict and fill it. Ask for a grade in math, english, literature and python, and store each one under its subject name:

grades = {} grades['math'] = int(input('math grade: ')) # ... and the same for the other three print(grades)
Do not forget the int(). input() always hands you a string, even when the user typed digits. Without it, '90' is text — and adding text together gives you '9078' instead of 168, if it does not raise TypeError first.
2

Add the average

Add a new key 'avg' whose value is the average of the four grades. You have to calculate it — nobody types it in.

💡 Hint: sum(...) adds up a collection of numbers and len(...) counts it. You already know how to get all the grades out of the dict in one go — it is one of the three views from the keys · values · items topic. Average = total ÷ how many.
3

Add the highest and the lowest

Add a key 'max' holding the best grade, and a key 'min' holding the worst.

💡 Hint: max(...) and min(...) take the same thing you just handed to sum(...).
The trap. Work out all three numbers before you put any of them into the dict. The moment 'avg' is inside, it becomes just another value — and max would then be picking the biggest out of the grades plus the average. Calculate first, insert after.
What your run should look like
math grade: 90 english grade: 78 literature grade: 65 python grade: 100 {'math': 90, 'english': 78, 'literature': 65, 'python': 100} {'math': 90, 'english': 78, 'literature': 65, 'python': 100, 'avg': 83.25, 'max': 100, 'min': 65}
4

The literature exam was cancelled 🗑️

The school drops literature this term. Remove that pair from the dict — key and grade, gone — then print the dict again.

We did not cover removing in class, so here is how it works — on a different dict. Read it, then do the same to your own:

d = {'a': 1, 'b': 2, 'c': 3} # way 1 — the del keyword, written in front of the pair del d['b'] print(d) # → {'a': 1, 'c': 3} # way 2 — the .pop() method, hands back the value it removed removed = d.pop('c') print(removed) # → 3 print(d) # → {'a': 1}
Both delete the pair. The difference: del just throws it away, while .pop() returns the value so you can still use it. Use whichever you like — now apply it to your own dict.
{'math': 90, 'english': 78, 'python': 100, 'avg': 83.25, 'max': 100, 'min': 65}
Look closely at that last line: 'avg', 'max' and 'min' are still the old numbers — they were worked out while literature was still there. A dict does not recalculate anything by itself.

מחיקה לא למדנו בשיעור, אז הנה איך היא עובדת — על מילון אחר. קראו, ואז עשו את אותו הדבר על המילון שלכם:

d = {'a': 1, 'b': 2, 'c': 3} # way 1 — the del keyword, written in front of the pair del d['b'] print(d) # → {'a': 1, 'c': 3} # way 2 — the .pop() method, hands back the value it removed removed = d.pop('c') print(removed) # → 3 print(d) # → {'a': 1}
שתיהן מוחקות את הזוג. ההבדל: del פשוט זורקת אותו, ואילו .pop() מחזירה את הערך כך שעדיין אפשר להשתמש בו. בחרו את מה שנוח לכם — ועכשיו יישמו את זה על המילון שלכם.
{'math': 90, 'english': 78, 'python': 100, 'avg': 83.25, 'max': 100, 'min': 65}
הסתכלו טוב על השורה האחרונה: 'avg', 'max' ו-'min' הם עדיין המספרים הישנים — הם חושבו כשהספרות עוד הייתה שם. מילון לא מחשב שום דבר מחדש בעצמו.
