The Seed — Random You Can Repeat 🎲

Random has been a coin toss until now: different every run, and nothing you could check. Today it gets a seed. Hand random.seed(7) the same number and you get the same "random" numbers back, every single time — which is what makes random testable. Then we use it: forty-two seeds, ten numbers each, and one question — which seed gives the biggest sum? That question needs a function, a loop, and the max-so-far pattern all working together.

Random, the Way You Know It 🎰

You met random back in lesson 8. Run this twice and you get two different answers — that is the whole idea of it.

import random print([random.randint(1, 100) for _ in range(5)]) print([random.randint(1, 100) for _ in range(5)])
[10, 69, 13, 47, 75] [8, 65, 28, 5, 12]

Run it again tomorrow and both lines will be different again. That is exactly what you want for a dice game — and exactly what you do not want when you are trying to find a bug, or compare two things fairly.

The problem. Suppose your program crashes on one particular set of random numbers. You run it again to look closer — and the numbers are different, so the crash is gone. You cannot fix what you cannot reproduce.

random.seed() — the Same Numbers Every Time 🎲

One line changes everything. Give random.seed() a number first, and the numbers that follow are decided by it.

import random random.seed(7) print([random.randint(1, 100) for _ in range(5)]) random.seed(7) print([random.randint(1, 100) for _ in range(5)]) random.seed(7) print([random.randint(1, 100) for _ in range(5)])
[42, 20, 51, 84, 7] [42, 20, 51, 84, 7] [42, 20, 51, 84, 7]

Three identical lines. And you will get those same five numbers when you run it, on your machine, tomorrow.

The seed is not the answer. It is the starting point the answers are worked out from.
It is still random in every way that matters — the numbers have no pattern you could guess, they are spread evenly, 42 is as likely as 43. It is just random that starts from a place you chose. The proper name for this is pseudo-random.
why it matters

Why Would Anyone Want Repeatable Random? 🔍

SituationWhy the seed saves you
Chasing a bugThe crash only happens on certain numbers. Fix the seed and the crash happens every time, so you can watch it.
Comparing two thingsTwo versions of a program, both handed exactly the same random data. Any difference is the program, not luck.
Marking homeworkEveryone's program runs on the same numbers, so everyone should get the same answer.
Today's questionSeed 37 always gives the same ten numbers — so "which seed is best" has one true answer, not a different one each run.
And where you must NOT use it. Never seed anything to do with security — passwords, tokens, a shuffled deck in a real card game. If the seed is guessable, so is everything that came out of it. For that there is secrets, not random.
01_random_ten.py

Forty-Two Seeds, One Winner 🏁

Here is the question written at the top of today's file:

Try every seed from 1 to 42.
For each one, generate 10 random numbers between 1 and 100 and add them up.
Which seed gave the highest sum? Print the seed and the sum.
# seed-1: [5, 7, 20, 90, ...] --> sum 217 ==> seed1: 217 # seed-2: [4, 6, 53, 88, ...] --> sum 201 ==> seed2: 201

Before writing anything, notice the shape of it. There are two loops here, one inside the other, and they are doing completely different jobs:

LoopRunsIts job
outer42 times, once per seedtry each seed and keep the best one so far
inner10 times, inside one seedadd up ten random numbers
Which is exactly the moment to reach for a function. Give the inner loop a name, and the outer loop becomes four readable lines. That is last week's habit, and this is what it is for.
01_random_ten.py

The Function Handles One Seed 🔧

One slot in, one number out. It knows nothing about the 42, and it does not need to.

import random def calc_sum_10(seed): ''' get a seed for random.seed sum 10 numbers return the sum :param seed: :return: sum of 10 numbers between 1-100 ''' random.seed(seed) # create random engine sum_10 = 0 # sum 10 random numbers for j in range(1, 10 + 1): random_number = random.randint(1, 100) sum_10 += random_number return sum_10
>>> calc_sum_10(1) 528 >>> calc_sum_10(1) 528 >>> calc_sum_10(37) 674

Call it twice with the same seed and you get the same answer twice. That is the seed doing its job — without it, this function would be useless for comparing anything.

LineWhat it is doing
random.seed(seed)set the starting point — first, before any number is drawn
sum_10 = 0the running total, starting empty
for j in range(1, 10 + 1)ten times. 10 + 1 is written that way on purpose: the 10 is the count you can see
sum_10 += random_numberthe accumulator pattern — add onto what is already there
return sum_10hand it back. No print in here
sum_10 += random_number is short for sum_10 = sum_10 + random_number. Two ways to write the same thing; the short one is what you will see in real code.

The Max-So-Far Pattern 🏆

The outer loop has one job: go through all 42 and remember the best. You cannot use max() here, because you need to know which seed it was, not just how big it got. So you keep two variables and update them together.

max_sum = None max_sum_seed = None for i in range(1, 42 + 1): sum_10_numbers = calc_sum_10(i) if max_sum is None or sum_10_numbers > max_sum: max_sum = sum_10_numbers max_sum_seed = i print(f"seed-{i}: sum {sum_10_numbers}") print(f"max_sum: {max_sum} max_sum_seed: {max_sum_seed}")
  1. Two empty boxes before the loopThe best sum so far, and the seed it came from. They must be created outside the loop, or they would be wiped clean on every turn.
  2. Work out this seed's sumOne call. All the work is behind the name.
  3. Is it better than the best so far?If yes, both boxes are updated together. Updating one without the other is the classic bug here — you end up reporting the right number next to the wrong seed.
  4. After the loop, announce the winnerOutside the loop, not inside. Inside, it would print 42 times.
The pair moves together, or the answer is nonsense.

Why It Starts at None, Not 0 ⚠️

Look at that if again. It has two halves, and the first one is doing real work:

if max_sum is None or sum_10_numbers > max_sum:

On the very first turn there is nothing to compare against. None means "I have not seen anything yet", and that first half makes the first seed win automatically, whatever it scored.

Why not just start at 0? Here it happens to work, because sums of positive numbers are always above 0. Change the data and it quietly breaks:
numbers = [-5, -3, -9] best = 0 # looks harmless for v in numbers: if v > best: best = v print(best)
0
0 was never in the list. The program answered with a number that does not exist in the data, and did not complain once.
start at None
best = None for v in numbers: if best is None or v > best: best = v
-3
start at 0
best = 0 for v in numbers: if v > best: best = v
0
is None, not == None. Both work, but is is the one Python people write — it asks "is this the actual None object", which is exactly the question.

Task 2 — Four Slots Instead of One 🔩

The second job in today's file: the same function, but stop hard-coding the 10, the 1 and the 100.

Make a function that gets a seed, how many numbers to draw, a min_range and a max_range — and returns the sum.
Then write a for loop that calls it.
def calc_sum(seed, how_many, min_range, max_range): ''' add up some random numbers, from a known starting point :param seed: the starting point for random :param how_many: how many numbers to draw :param min_range: smallest number allowed :param max_range: biggest number allowed :return: the sum of them ''' random.seed(seed) total = 0 for i in range(how_many): total += random.randint(min_range, max_range) return total
print(calc_sum(1, 10, 1, 100)) print(calc_sum(37, 10, 1, 100)) print(calc_sum(1, 5, 1, 6)) # five dice rolls
528 674 12

Same function, three completely different jobs. The first two lines are the old calc_sum_10; the third one is rolling dice, which the old version could never have done.

calc_sum_10(seed) 10, 1 and 100 baked in
→
calc_sum(seed, how_many, min_range, max_range)
This is the same lesson as the tax function two weeks ago: a number written inside the body is a decision you took away from whoever calls it. A parameter hands the decision back.
range(how_many) counts 0, 1, 2 … and range(1, how_many + 1) counts 1, 2, 3 …. Both go round exactly how_many times, and here the counter is never used — so either is fine. When you genuinely do not use it, Python people write it as _.

The Whole Thing, Running 🏃

import random def calc_sum_10(seed): random.seed(seed) sum_10 = 0 for j in range(1, 10 + 1): random_number = random.randint(1, 100) sum_10 += random_number return sum_10 max_sum = None max_sum_seed = None for i in range(1, 42 + 1): sum_10_numbers = calc_sum_10(i) if max_sum is None or sum_10_numbers > max_sum: max_sum = sum_10_numbers max_sum_seed = i print(f"seed-{i}: sum {sum_10_numbers}") print(f"max_sum: {max_sum} max_sum_seed: {max_sum_seed}")
seed-1: sum 528 seed-2: sum 432 seed-3: sum 546 seed-4: sum 334 seed-5: sum 654 seed-6: sum 466 seed-7: sum 418 seed-8: sum 327 ... seed-40: sum 557 seed-41: sum 501 seed-42: sum 420 max_sum: 674 max_sum_seed: 37
Seed 37 wins, with 674. And here is the proof that the whole lesson worked: you will get 37 and 674 too. Run it on your machine, right now — same answer. Without random.seed() the winner would be a different seed every single time you ran it, and the question would have no answer at all.
