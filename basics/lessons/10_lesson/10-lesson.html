Classroom 1 — Max, Min and Average

The task: ask how many students are in the class, then read that many grades. Every grade must be between 0 and 100 — anything else is rejected and asked again. At the end print the highest grade, the lowest grade and the average.

for → we know how many students while → we do NOT know how many mistakes 3 trackers: max / min / sum
The full program
max_grade = -1 # lower than any legal grade min_grade = 101 # higher than any legal grade sum_grade = 0 num_students = int(input('number of students: ')) for i in range(num_students): # ① exactly num_students rounds grade = int(input('grade?')) while grade < 0 or grade > 100: # ② while it is NOT valid print('Illegal grade, must be between 0-100') grade = int(input('grade?')) # ask again! if grade >= max_grade: max_grade = grade if grade <= min_grade: min_grade = grade sum_grade += grade print(f'max grade: {max_grade}') print(f'min grade: {min_grade}') print(f'avg grade: {sum_grade / num_students}')
number of students: 3 grade?80 grade?140 Illegal grade, must be between 0-100 grade?-5 Illegal grade, must be between 0-100 grade?90 grade?70 max grade: 90 min grade: 70 avg grade: 80.0
A for and a while in the same program

This is the first time the two loops work together, and each one is doing the job it is good at:

LoopIts jobWhy that loop
for i in range(num_students) read one grade per student we know the count before we start — the user just told us
while grade < 0 or grade > 100 keep asking until the grade is legal nobody knows how many times the user will type junk — it could be zero times or ten
Read the while out loud: "while the grade is not valid — complain and ask again". If the first grade was already fine, the condition is False immediately and the loop body runs zero times. That is not a bug — that is the normal, happy case.
The trap: forgetting the second input inside the while. Without it grade never changes, the condition stays True forever, and the program prints Illegal grade until you kill it. Every while needs something in its body that can make the condition become False.

Printing with an f-string

Two ways to print the same sentence — the second one is what we will use from now on:

a = 1 b = 2 c = 3 print(a, '+', b, '=', c) # commas: print adds a space between the pieces print(f'{a} + {b} = {c}') # f-string: one sentence, values in { }
1 + 2 = 3 1 + 2 = 3
The f before the quote turns the string into a formatted string. Anything inside { } is evaluated and its value dropped into place — even an expression: f'sum: {a + b}' prints sum: 3. Without the f you get the literal text {a} + {b}.

None — The Value That Means "Nothing Yet"

Every tracker so far had to start at some number, and we had to invent that number: max_grade = -1, min_grade = 101. It works when you know the legal range. But what is the starting value for "the largest number the user will type" when the user may type any number, positive or negative?

There is no such number. max_number = 0 is wrong the moment every input is negative — the program would proudly announce a maximum of 0, a number the user never typed.

Python has a value for exactly this situation:

max_number = None # "there is no maximum yet"
max_number
None
honest: nothing yet
max_number
0
a lie: 0 is a real number
the user never typed
max_number
-5
after the first input
— now it is real
Three things to know about None
FactMeaning
Capital NNone — not none, not NONE, not "None". Python is case-sensitive and none gives a NameError.
It is not 00 is a number you can add. None is the absence of a value. None + 1 is a TypeError, not 1.
It is not ""An empty string is still a string. None is not a string at all.
Testing for None — use is
if max_number is None: # ✅ the Python way ... if max_number == None: # works, but nobody writes it ...
== asks "do these two have the same value?". is asks "are these literally the same thing?". There is only ever one None in a running Python program, so is None is both faster and the accepted style. Its opposite is is not None.
The pattern you will use forever

Start at None, then on every round ask "is this the first value, or is it bigger than the best so far?":

max_number = None # ... inside the loop ... if max_number is None or num > max_number: max_number = num
The order of the two tests matters. Python reads or left to right and stops as soon as one side is True — so when max_number is None is True, the comparison num > max_number is never executed. Swap the two sides and the program crashes on the very first round with
TypeError: '>' not supported between instances of 'int' and 'NoneType'.
This is called short-circuit evaluation, and you have been using it since the and/or lesson. Here it stops being a curiosity and becomes the thing that keeps your program alive.
Printing None is fine
print(f'max: {max_number}')
max: None
If the loop never ran, the variable is still None and the program says so — an honest None instead of a made-up 0. That is exactly the report we want.

Classroom 3 — Biggest Even, Biggest Odd

Read numbers until 0. Print the largest even number and the largest odd number. If one of the groups stayed empty — print None for it.

max_even = None # Zugi max_odd = None # e-Zugi while True: num = int(input('number [0 to exit]?')) if num == 0: break if num % 2 == 0: if max_even is None or num > max_even: max_even = num if num % 2 == 1: if max_odd is None or num > max_odd: max_odd = num print(f'max even: {max_even}') print(f'max odd: {max_odd}')
Three runs from the whiteboard

The third row is the whole reason None exists in this program. With two separate ifs (not elif) each group asks its own independent question, and each keeps its own independent "nothing yet".

The Throwaway Variable _

A for loop always needs a name for its counter, even when the loop is only there to repeat something. Look at these two — they do the exact same thing:

i is used
for i in range(5): print(f'round {i}') # i matters
i is never used
for _ in range(5): print('hello') # repeat 5×
_ is an ordinary variable name — nothing magic. Python does not treat it specially. What is special is the message it sends to the reader: "this loop needs a counter, but I am never going to look at it".
Read it as "do this N times"
# print 50 random numbers between 1 and 36 for _ in range(50): num = random.randint(1, 36) print(num, end=' ') print()
Nothing inside the body mentions the counter — the loop is pure repetition. Using _ makes that obvious at a glance, and it also stops the editor from warning you about an unused variable.
WriteWhen
for i in range(n):the body uses i — as a row number, a counter, a value to print
for _ in range(n):the body ignores the counter — "just do it n times"
Both are correct code. Using i and ignoring it is not an error — but a reader who sees i starts hunting for where it is used. _ saves them the search.

import — Borrowing Code Someone Else Wrote

Until today every tool we used — print, input, int, range — was built in: always there, no setup. But Python ships with hundreds more tools that are not loaded by default. They live in modules, and you ask for one with import.

import random # at the TOP of the file, once
🧰 what import random puts on your desk
random.randintwhole number in a range random.randomfloat 0.0 → 0.999… random.choicepick one item random.randrangepick from a range with a step random.sampleseveral, no repeats random.seedmake it repeatable
Why the dot?

import random does not dump the names into your program. It creates one name — random — and everything inside is reached through it:

num = random.randint(1, 6) # module . function
Drop the dot and Python has never heard of the name: randint(1, 6) gives NameError: name 'randint' is not defined. Forget the import line and you get the same error about random itself.
Never name your file after a module you import. A file called random.py makes Python import your file instead of the real one — math.py and time.py are the same landmine.
Reading the manual without leaving Python — help()

Do not remember whether randint(1, 6) can return 6? Ask Python itself:

import random help(random.randint)
Help on method randint in module random: randint(a, b) method of random.Random instance Return random integer in range [a, b], including both end points.
"including both end points" — that one sentence answers the question. Note how different this is from range(1, 6), which stops at 5. Write help(random.random), help(print), help(str) — every built-in tool carries its own documentation. In PyCharm, Ctrl+Q on a function name shows the same text in a popup.
01_random.py

randint — Rolling Dice, and seed — Rolling the Same Dice Twice

The whole point of a game is that you cannot predict it. random.randint(a, b) gives a whole number between a and b, both included:

import random x = random.randint(10, 20) # 10, 11, 12 ... 19 or 20 print(x)
← random.randint(1, 6), five times
randint includes the top, range does not. random.randint(1, 6) can return 6. range(1, 6) stops at 5. Two functions, two different rules — this is the single most common mix-up of the lesson.
Many numbers — _ and randint together
# print 50 random numbers between 1 and 36 for _ in range(50): num = random.randint(1, 36) print(num, end=' ') print()
Run it twice and you get 50 completely different numbers. Which is wonderful for a game — and a nightmare when you are trying to debug one.
random.seed() — the same "random" every time

Computers cannot actually be random. They run a formula that produces numbers that look random, and that formula needs a starting point — the seed. Normally Python picks the seed from the clock, so every run differs. Choose the seed yourself and the whole sequence becomes repeatable:

import random random.seed(42) for _ in range(50): num = random.randint(1, 36) print(num, end=' ') print()
run #1 — seed 42

run #2 — seed 42

Change only the range and the sequence changes with it — but it is still the same sequence on every run:

SituationSeed or not?
a real game — dice, cards, lotteryno seed. Let the clock decide, so every game is different.
hunting a bug that only shows up "sometimes"seed it. Same numbers every run = a bug you can reproduce.
a homework whose output the teacher must matchseed it. Everyone gets identical output.
42 is not magic — any number works, and a different seed gives a different (but equally repeatable) sequence. Call random.seed() once, at the start. Calling it inside a loop re-starts the sequence every round and you get the same number over and over.

Four More Tools from the random Box

One tool at a time — use next and prev at the bottom to move through them.

1

random.random() — a float between 0 and 1

help(random.random) float_rnd = random.random() print(float_rnd) # 0.0 up to 0.999999...
0.6394267984578837
Note the empty parentheses — random.random() takes no arguments. It always gives the same range: 0.0 is possible, 1.0 never is. It is the raw material every other function in the module is built on, and it is what you want for percentages: if random.random() < 0.3: happens roughly 30% of the time.
2

random.choice(...) — pick one out of a group

randint only gives numbers. choice picks one item out of a group you write yourself — numbers, text, even None:

# random between choices: [1, 3, 5, None, -2, 7, "hello"] for _ in range(10): print(random.choice([1, 3, 5, None, -2, 7, "hello"]), end=" ") print()
5 3 None 7 1 1 hello -2 1 5
The square brackets make a list — the subject of a whole future lesson. For today just read it as "one of these". Notice items can repeat (1 came out three times) and that a list can hold different kinds of things at once, None included.
3

random.randrange(start, stop, step) — a random member of a range

Same three numbers as range(), same rules — but instead of walking through them all, it hands you one at random:

# the numbers of: for _ in range(3, 30 + 3, 3) → 3 6 9 12 15 18 21 24 27 30 # identical to: random.choice([3, 6, 9, 12, 15, 18, 21, 24, 27, 30]) print(random.randrange(3, 30 + 3, 3))
18
FunctionTop valueStep
random.randint(1, 6)included — 6 can come outalways 1
random.randrange(1, 6)excluded — never 6any step you like
randrange follows the range rule (stop excluded), randint does not. Remember it as: randrange behaves like range.
4

random.sample(group, k) — several, with no repeats

Call randint six times for a lottery draw and sooner or later the same ball comes out twice. sample is the function that cannot do that — it takes k different items:

# no repetition - 1 time each number print(random.sample(range(1, 10 + 1), 10))
[6, 3, 7, 10, 1, 8, 5, 2, 4, 9]
637101 85249
All ten numbers 1..10 came out, each exactly once, in a shuffled order — sample with k equal to the group size is a shuffle. Ask for fewer and you get a draw: random.sample(range(1, 37), 6) is a lottery ticket.
Asking for more than exists — random.sample(range(1, 5), 10) — raises ValueError: Sample larger than population. There simply are not 10 different numbers to give you.
