Functions Into Files — and the Tuple 🧰

Two habits and one new type. First: stop writing a program from the top down and start writing it as a story — call the functions you wish you had, leave them empty with pass, and only then go and fill them in. Second: once those functions work, they do not have to live in the same file as the story. Move them to students_lib.py, import them back, and the main file becomes ten readable lines. And then the tuple — a list that locked its own door.

03_func_prog.py

Write the Story First 📖

Here is the way most people start a guessing game: open a file and type the first line that runs. Then the second. Half an hour later there are eighty lines, three of them are about drawing a message, four are about validating input, and none of it has a name.

Today we do it backwards. Write the story first — the main program, top to bottom, calling functions that do not exist yet. You are allowed to call anything you wish existed, because you are the one who will write it in a minute.

print('Welcome to the number guessing game!') random_number = get_random_number(1, 100) guesses = 0 while True: guesses += 1 user_guess = get_user_guess(1, 100) if user_guess == random_number: print(f'Congratulations! You guessed the number {random_number} in {guesses} guesses') break message = get_game_message(user_guess, random_number) print(message) print('Game over! see you again soon')

Read it out loud. Get a random number. Ask the user to guess. If it matches, congratulate and stop. Otherwise work out the message and print it. That is the whole game, and there is not one line of logic in it yet.

Notice what the story just did for you: it named the three hard parts and it decided their signatures. get_game_message(user_guess, random_number) takes two slots and returns text — you knew that before you wrote a single line inside it.
The story decides what you need. Only then do you go and build it.
03_func_prog.py

A Function That Does Nothing — On Purpose 🪧

Python will not accept an empty body. A def line with nothing under it is a SyntaxError. So you put pass there: a word that means nothing to do here yet, move on.

def get_random_number(): pass def get_user_guess(): pass def get_game_message(): pass

Three stubs at the top of the file, the story underneath, and the file opens — Python reads all three def lines happily. This is the whole trick: your program exists, in outline, before any of it works.

It opens. It does not run. Run it now and you get exactly this:
Welcome to the number guessing game! Traceback (most recent call last): File "03_func_prog.py", line 20, in <module> user_guess = get_user_guess(1, 100) TypeError: get_user_guess() takes 0 positional arguments but 2 were given
That error is not a problem — it is a to-do list. The story called get_user_guess(1, 100) with two arguments, so the stub needs two slots. The story is telling the function what shape to be.
What the story saysWhat the stub must become
get_random_number(1, 100)two slots, returns a number
get_user_guess(1, 100)two slots, returns the guess
get_game_message(user_guess, random_number)two slots, returns a string
pass is not a return. A stub with only pass hands back None — exactly the trap from last lesson. It is a placeholder, and it is meant to be replaced.
03_func_prog.py

Now Fill Them In, One at a Time ✏️

The story is fixed. Each stub is now a small, closed problem you can solve without thinking about the rest of the game.

1 · get_random_number(low, high)
import random def get_random_number(low, high): ''' pick the secret number :param low: smallest allowed :param high: biggest allowed :return: a random number between them ''' return random.randint(low, high)
2 · get_user_guess(low, high)

This one owns the whole job of getting a valid guess. It does not give up until it has one — and the loop that used to clutter the main program lives in here now.

def get_user_guess(low, high): ''' ask until the player types a number in range :param low: smallest allowed :param high: biggest allowed :return: the player's guess ''' while True: guess = int(input(f'Guess a number between {low} and {high}: ')) if low <= guess <= high: return guess print('number not in range')
return inside the while is the exit. A good guess walks out of the loop and out of the function in one move — no break, no flag variable.
3 · get_game_message(user_guess, random_number)
def get_game_message(user_guess, random_number): ''' the hint after a wrong guess :param user_guess: what the player said :param random_number: the secret :return: 'Too low!' or 'Too high!' ''' if user_guess < random_number: return 'Too low!' return 'Too high!'
Welcome to the number guessing game! Guess a number between 1 and 100: 50 Too low! Guess a number between 1 and 100: 75 Too high! Guess a number between 1 and 100: 62 Congratulations! You guessed the number 62 in 3 guesses Game over! see you again soon
Three functions, three docstrings, and a main program you can still read a month from now. The order matters: story → stubs → bodies. Never the other way round.
students_lib.py

Move the Functions Into Their Own File 📦

Once the functions work they stop being interesting. Nobody reading the program wants to scroll past forty lines of input validation to find out what the program does. So we take them out.

Make a second file next to the first one. Ours is called students_lib.py — a module. It holds functions and nothing else: no print at the bottom, no story, just definitions.

# students_lib.py def get_number_of_students(min_stud=2, max_stud=50): ''' returns the number of students in the list :param min_stud: :param max_stud: :return: number of students ''' while True: number = int(input(f"Enter a number between {min_stud} and {max_stud}: ")) if min_stud <= number <= max_stud: return number print('number not in range') def get_student_names(num_of_stud): names = [] for i in range(num_of_stud): name = input(f"Enter the name of student {i + 1}#: ") names.append(name) return names def create_dict(names, grades): result = {} for i in range(len(names)): result[names[i]] = grades[i] return result def get_max_name_grade(students): max_name = max(students, key=students.get) return max_name, students[max_name]
max(students, key=students.get) walks the dictionary's keys but compares them by their values — so it hands back the name of the best student, not the grade. Then students[max_name] fetches the grade itself.
Two values out of one function. return max_name, students[max_name] returns both — and the thing that comes back is a tuple. That is the bridge to the second half of this lesson.
02_func_prog.py

Import Them Back 🔌

The functions are in another file now, so the main program has to go and fetch them. That is what import is for — the same word you already used for random, except this time the module is yours.

from students_lib import *

Read it as: from the file students_lib.py, bring in everything. After that line, every function in that file can be called by its plain name, as if you had typed it here.

Way to importHow you call itWhen
from students_lib import *get_student_names(5)what we use today — short and readable
from students_lib import create_dictcreate_dict(n, g)when you only want one or two of them
import students_libstudents_lib.create_dict(n, g)the safest — you can always see where it came from
One file holds the tools. The other holds the story. Both stay short.
Same folder. students_lib.py has to sit next to the file importing it, or Python answers ModuleNotFoundError: No module named 'students_lib'. And do not name your file random.py — Python would find yours instead of the real one.

The Whole Program, in Ten Lines 📜

Here is the entire students program. Every hard part is behind a name, and what is left reads like a paragraph of English.

from students_lib import * num_of_stud = get_number_of_students(min_stud=2, max_stud=50) list_of_names = get_student_names(num_of_stud) list_of_grades = get_student_grades(num_of_stud) dict_students = create_dict(list_of_names, list_of_grades) max_name, max_grade = get_max_name_grade(dict_students) print(f"max grade was {max_grade} and the student was {max_name}")

Look at the second-to-last line again:

max_name, max_grade = get_max_name_grade(dict_students)

The function returned two things at once, and two variables caught them. That pair travelling together is a tuple, and unpacking it into two names like this is one of the most common things tuples are used for in real Python.

01_tuple.py

The Tuple — a List That Locked Its Door 🔒

You know four ways to hold several values already. Here is the fifth, and the last one of the set:

TypeLooks likeThe rule
list[1, 2, 3]ordered, duplicates fine, changeable
set{1, 2, 3}no order, no duplicates
dict{'a': 1}key → value
tuple(1, 2, 3)ordered, duplicates fine, cannot be changed

A tuple is a list that has been locked. Everything you can read from a list you can read from a tuple. Everything that would change it is gone.

t1 = ('a', 'b', 'c') t2 = ('d', 'e', 'f') print(t1, t2)
('a', 'b', 'c') ('d', 'e', 'f')
Try to change one and Python stops you:
t[0] = 'z' TypeError: 'tuple' object does not support item assignment t.append('d') AttributeError: 'tuple' object has no attribute 'append'
No append, no remove, no sort, no clear. Those methods do not exist on a tuple, because all of them change things.
The comma is what makes it 🚨

Not the brackets. This catches everybody once:

not a tuple
x = (42) print(type(x))
<class 'int'>
a tuple
x = (42,) print(type(x))
<class 'tuple'>
And you can build one from anything you can loop over: tuple([1, 2, 3]) → (1, 2, 3), tuple('abc') → ('a', 'b', 'c').
01_tuple.py

Index & Slice — Exactly Like a List 🔢

Reading is unchanged. Positions start at 0, negatives count from the end, and a slice hands you a new tuple.

t1 = ('a', 'b', 'c') t2 = ('d', 'e', 'f') print(t1[0]) print(t2[0]) print(t2[-1]) print(t2[::-1]) t3 = (0, 1, 2, 3, 4, 5) # Items at index 1, 2, 3 print(t3[1:4])
a d f ('f', 'e', 'd') (1, 2, 3)
The slice takes 1, 2 and 3 — it stops before 4. Same rule as lists and strings.
A slice of a tuple gives you a new tuple. Nothing was changed — the original is still sitting there untouched, which is the whole point.
01_tuple.py

Two Methods, and Two Ways to Make a New One 🧮

A list has about eleven methods. A tuple has two — and that is not a limitation, it is the promise: neither one changes anything.

t = (1, 2, 2, 3, 2, 4, 2) n = t.count(2) print(t, 't.count(2)=', n) t = ('cat', 'dog', 'bird', 'dog') print(t, 't.index("dog")=', t.index('dog'))
(1, 2, 2, 3, 2, 4, 2) t.count(2)= 4 ('cat', 'dog', 'bird', 'dog') t.index("dog")= 1
MethodAnswersNote
t.count(x)how many times x is in there0 if it is not
t.index(x)the position of the first xValueError if it is not there — check with in first
Making new tuples out of old ones

You cannot change a tuple. You can always build a new one.

a = (1, 2, 3) b = (4, 6, 1) result = a + b print(a, '+', b, '=', result) print(sorted(b, reverse=True)) print(tuple(sorted(b, reverse=True)))
(1, 2, 3) + (4, 6, 1) = (1, 2, 3, 4, 6, 1) [6, 4, 1] (6, 4, 1)
Watch the brackets on that middle line. sorted() always hands back a list, whatever you feed it — so [6, 4, 1], with square brackets. Want a tuple back? Wrap it: tuple(sorted(b, reverse=True)).
There is no b.sort() here, and there cannot be — .sort() rearranges the thing in place, and a tuple has no in-place. sorted() leaves the original alone and returns something new. That is exactly the distinction from last lesson.

Asking Questions About a Tuple ❓

The same words you used on lists and strings all work here, because none of them change anything.

t = ('apple', 'banana', 'cherry') print(t, "banana in t?", 'banana' in t) print(t, "mango not in t?", 'mango' not in t)
('apple', 'banana', 'cherry') banana in t? True ('apple', 'banana', 'cherry') mango not in t? True

(3, 1, 4, 1, 5, 9) len(t) 6 (3, 1, 4, 1, 5, 9) min(t) 1 (3, 1, 4, 1, 5, 9) max(t) 9 (3, 1, 4, 1, 5, 9) sum(t) 23

max9

min, max and sum want values that can be compared. On ('apple', 'banana'), min still works — it compares alphabetically. On sum of strings it does not: TypeError.

Why the Lock Is Useful: a Tuple Can Be a Key 🔑

A dictionary key has to be something that never changes — otherwise the dictionary would lose track of where it filed it. A list can change, so a list can never be a key. A tuple cannot, so it can.

d = {(1, 2): ('a', 'b')} # tuple could be used as key in dict print(d) print(d[ (1,2) ])
{(1, 2): ('a', 'b')} ('a', 'b')
tuple key — fine
d = {(1, 2): 2}
list key — never
d = {[3, 4]: 2} TypeError: unhashable type: 'list'

That is what real code uses tuple keys for: a coordinate, a date, a pair of names — anything where the key is naturally two or three values instead of one.

The catch nobody expects ⚠️

The tuple is locked. What is inside it might not be.

a = [1, 2] tup = (a, 12) print(tup) a.clear() print(tup)
([1, 2], 12) ([], 12)

Nobody touched tup. The tuple still holds exactly the same two items it always held — the same list, and the number 12. But that list emptied itself, and the tuple has no say in it.

The tuple promises which things it holds, not that those things never change.
And that is why a tuple with a list inside it still cannot be a key:
tup = ([3, 4], 12) d1 = {tup: 2} TypeError: unhashable type: 'list'
Python checks the whole way down. One changeable thing anywhere inside and the answer is no.

The pattern for the homework 🧩

Every one of tonight's tasks is the same shape, and here it is in full. You cannot grow a tuple, so you collect into a list and turn it into a tuple at the end.

# function that gets tuple return new tuple only from even numbers def get_even(tup): result = [] # 1. an empty LIST to collect in for num in tup: # 2. walk the tuple if num % 2 == 0: # 3. is this one a keeper? result.append(num) # yes - into the list result_tup = tuple(result) # 4. lock the list into a tuple return result_tup # 5. hand it back input_fun = (1, 2, 4, 7, 9, 10, 14) print(input_fun) print(get_even(input_fun))
(1, 2, 4, 7, 9, 10, 14) (2, 4, 10, 14)
  1. Start with an empty listYou cannot append to a tuple, so the collecting happens in a list.
  2. Loop over the tuple you were givenReading it is always allowed.
  3. Test each item, keep the ones you wantThe loop and the collecting stay the same every time; only what happens inside changes.
  4. tuple(result)Lock the finished list.
  5. return itThe original tuple is untouched — a brand new one comes back.
Learn this shape once and all three of tonight’s functions are the same five steps with a different middle.

Homework — Three Tuple Functions ✍️

Three functions. Every one of them follows the shape from get_even: an empty list to collect in, a loop, append, then tuple(...) and return.

Rules for all three:
  1. Every function gets a docstring with :param for each slot and :return: for the answer.
  2. Return a tuple, do not print. The print happens outside, on what came back.
  3. Call each one at least twice with different values, and print what came back.
1 · reverse_tuple(tup) 🔄

Takes a tuple, returns a new tuple with the same items in the opposite order. The tuple you were given must come back untouched — you are building a second one.

def reverse_tuple(tup): # docstring here # empty list, walk the tuple backwards, append, tuple(...), return print(reverse_tuple( (1, 2, 3, 4) )) print(reverse_tuple( ('a', 'b', 'c') )) print(reverse_tuple( () ))
(4, 3, 2, 1) ('c', 'b', 'a') ()
Two honest roads. Walk it backwards yourself with for i in range(len(tup) - 1, -1, -1): and append each tup[i] — or let the slice do it: tup[::-1] already hands back a reversed tuple. Try the loop first, then check yourself against the slice.
2 · random_tuple(length) 🎲

Takes a number — how long the tuple should be — and returns a tuple of that many random numbers between 1 and 100.

import random def random_tuple(length): # docstring here # loop 'length' times, append a random number each time print(random_tuple(5)) print(random_tuple(3)) print(len(random_tuple(10)))
(42, 20, 51, 84, 7) (10, 69, 13) 10
Your numbers will be different every run — that is correct. The two things that must always be true: the tuple has exactly length items, and every one of them is between 1 and 100. Check the length with len(), not with your eyes.
random.randint(1, 100) includes both ends, so 1 and 100 can both come up. This is the only task tonight where the input is a plain number instead of a tuple.
3 · flat_dict(d) 🫓

Takes a dictionary and returns one flat tuple: every key followed by its value, in order.

{'a': 1, 'b': 2, 'c': 3}
→
('a', 1, 'b', 2, 'c', 3)
def flat_dict(d): # docstring here # for each key: append the key, then append the value print(flat_dict( {'a': 1, 'b': 2, 'c': 3} )) print(flat_dict( {'name': 'dana', 'age': 29} )) print(flat_dict( {} ))
('a', 1, 'b', 2, 'c', 3) ('name', 'dana', 29) ()
for key in d: walks the keys, and d[key] fetches the value — so it is append twice inside one loop. Notice the result mixes strings and numbers in one tuple: that is allowed, and it is why the answer is a tuple and not a dict any more.
