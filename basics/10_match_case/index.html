Topic 10

match & case 🎚️

When every branch of a long if / elif chain compares the same variable against a fixed value, you end up typing that variable name over and over. match names it once and lists the answers underneath — shorter to write, and much easier to read.

volume.py
match volume: case 1: print('very quiet') case _: print('invalid')
1

The Shape

Three parts: the word match with the variable, then one case per value, each with an indented body — exactly like if.

match number: # the variable, named ONCE case 1: # is it 1? print('You entered one') case 2: print('You entered two') case 3: print('You entered three')
Enter a number: 2 You entered two

The same program with if / elif — notice number == repeated on every line:

if number == 1: print('You entered one') elif number == 2: print('You entered two') elif number == 3: print('You entered three')
💡 Both programs do exactly the same thing. match is not faster — it is less repetitive. That is the entire reason it exists.
2

case _ — the default

An underscore matches anything. It is the else of a match block, and it goes last:

match number: case 1: print('one') case 2: print('two') case _: # anything else print('not 1 or 2')

Leave it out and a non-matching value simply does nothing — no error, no output:

match name: case 'danny': print('Hello Danny') case 'shemesh': print('Hello Shemesh')
Enter a name: rachel (nothing at all)
⚠️ This silence is the most common match bug. It is not a crash, so it is easy to miss — always ask yourself whether you want a case _.
3

Several values in one case — |

To catch more than one value with a single branch, separate them with |. Read it as "or":

match day: case 6 | 7: # 6 OR 7 print('Weekend') case _: print('A work day')

It works with any number of values, and with strings too:

match volume: case 3 | 4: print('low') case 9 | 10: print('max volume') match answer: case 'y' | 'yes' | 'Y': print('Starting...')
⚠️ Inside a case the "or" symbol is |, not the word or. Writing case 6 or 7: does not do what you expect.
4

The Four Rules

RuleWhat it means
Only one case runsPython takes the first case that matches and jumps out. If you know switch from another language — there is no break here.
Order mattersCases are checked top to bottom. A case _ placed first would swallow everything.
Colons + indentationEvery case ends with : and its body is indented, exactly like if.
Python 3.10+match was added in Python 3.10. On an older version you get a SyntaxError on the match line.
💡 match and case are "soft keywords" — you can still have a variable called match. Please do not; it makes the code very confusing to read.
5

When NOT to use it

match is narrower than if. It compares for equality and nothing else, so these three jobs still belong to if / elif:

You need…UseWhy
Ranges — grade >= 90if / elifcase cannot say "bigger than"
Two different variables — age > 18 and cash > 5000if / elifthere is no single variable to put after match
Only two optionsif / elsea whole match block for two branches is more typing
💡 The quick test: if you are typing the same variable name at the start of every elif, that is match asking to be used. If your conditions contain <, >, and or or — stay with if / elif.
6

A Real Program — dealing a card

A deck runs 2 3 4 … 10 J Q K A. Computers compare numbers, not letters, so we draw 2–14 and use match to turn the top four into their letters:

import random card_number = random.randint(2, 14) match card_number: case 11: display = 'J' case 12: display = 'Q' case 13: display = 'K' case 14: display = 'A' case _: # 2..10 show themselves display = card_number suit = random.choice(["❤️", "♦️", "♣️", "♠️"]) print(f"{display}{suit}")
Q♦️
💡 One case _ handles the entire boring 2–10 range in a single line. Written as if/elif this needs five card_number == comparisons.
