Lists — Advanced 🚀

Every three-line "empty list, loop, append" collapses into one comprehension. all and any answer "every one?" and "at least one?" with no loop at all. sort, sorted, reverse and key= put things in order. And then the fact that catches everyone: b = a does not copy a list — which is exactly why .copy() and .clear() exist.

01_comprehension.py
squares = [] for n in nums: squares.append(n * n) # ↓ the same thing squares = [n * n for n in nums]
1

The comprehension

Read it left to right: "n times n — for every n in nums". The square brackets are what make the answer a list:

nums = [3, 8, 15, 4, 23, 42, 7, 16] # the long way — 3 lines squares = [] for n in nums: squares.append(n * n) # the comprehension — 1 line, same answer squares = [n * n for n in nums] print(squares)
[9, 64, 225, 16, 529, 1764, 49, 256]
[ n * n what goes in each cell for n in nums ]
💡 A comprehension is for building a list. If you only want to print, or to call input() each round, keep the normal for.
2

Two ifs, two different places

This is the one thing to get right. An if at the end filters. An if…else at the front chooses:

filter — at the end, no else
[n for n in nums if n > 10]
[15, 23, 42, 16] ← 4 items out of 8
ternary — at the front, needs else
[n if n > 10 else 0 for n in nums]
[0, 0, 15, 0, 23, 42, 0, 16] ← all 8, changed
PieceWhere it goesDecides
the expressionfirst, before forwhat lands in each cell
the loopin the middlewhat you walk over
if … (filter)last, no elsewhether the item goes in at all
if … else … (ternary)at the frontwhich of two values goes in
# both at once: doubled, but only the ones above 10 print([n * 2 for n in nums if n > 10])
[30, 46, 84, 32]
⚠️ Writing else at the end is a SyntaxError. If you need an else, the whole if…else belongs at the front.
3

It works on anything you can loop

Strings, range, the result of .split() — all fair game, and every string method from the strings lesson comes along:

names = ['danny', 'moshe', 'suzi', 'sharon'] print([name.upper() for name in names]) print([len(name) for name in names]) print([name for name in names if 's' in name]) print([i * i for i in range(1, 6)]) print([c for c in 'python']) print([int(x) for x in '20 5 13 7'.split()])
['DANNY', 'MOSHE', 'SUZI', 'SHARON'] [5, 5, 4, 6] ['moshe', 'suzi', 'sharon'] [1, 4, 9, 16, 25] ['p', 'y', 't', 'h', 'o', 'n'] [20, 5, 13, 7]
💡 That last line is the most useful comprehension there is. .split() hands you a list of strings; the comprehension turns every one into an int. One line to read a whole row of numbers from the user.
4

all & any — two questions, no loop

"Did everybody pass?" used to be six lines with a flag and a break. Now it is one:

grades = [88, 91, 76, 95, 60] print(all(g >= 60 for g in grades)) # did EVERYBODY pass? print(any(g == 100 for g in grades)) # any perfect score? print(any(g > 90 for g in grades)) print(all(g > 90 for g in grades))
True False True False

Underneath, both take a list of True/False values — which is exactly what a comprehension builds:

passed = [g >= 60 for g in grades] print(passed) # [True, True, True, True, True] print(all(passed)) # True
ExpressionResultWhy
all([True, True, False])Falseone of them broke the rule
any([True, True, False])Trueat least one was true
all([5, 0, 9])False0 counts as falsy
all([])Truenothing broke the rule — there was nothing to break it
any([])Falsenothing was true, because there was nothing
⚠️ all([]) being True surprises everyone once. If "empty" should not count as a pass, ask both: if len(grades) > 0 and all(g >= 60 for g in grades):
💡 Both give a plain boolean, so give it a name and your if reads like English: everyone_passed = all(g >= 60 for g in grades).

sort vs sorted

Same job, one crucial difference: one edits your list, the other builds a new one.

.sort() — edits the list
scores = [45, 12, 99, 3, 67] scores.sort() print(scores)
[3, 12, 45, 67, 99] ← the original changed
sorted() — builds a new one
scores = [45, 12, 99, 3, 67] ordered = sorted(scores) print(ordered) print(scores)
[3, 12, 45, 67, 99] [45, 12, 99, 3, 67] ← untouched
lst.sort()sorted(lst)

⚠️ The same trap as append. .sort() returns None, so scores = scores.sort() throws your whole list away. Call scores.sort() on its own line — or use sorted().

reverse flips — it does not sort

The classic mix-up. .reverse() turns the list back to front exactly as it stands:

nums = [45, 12, 99, 3, 67] nums.reverse() print(nums) # flipped — and still not sorted! nums.sort(reverse=True) print(nums) # THIS is biggest-first
[67, 3, 99, 12, 45] [99, 67, 45, 12, 3]
WrittenDoes whatTouches the original?Gives back
lst.reverse()flips the current orderyesNone
lst[::-1]flips the current ordernoa new list
lst.sort(reverse=True)sorts, biggest firstyesNone
sorted(lst, reverse=True)sorts, biggest firstnoa new list
💡 The pattern behind the whole page: methods with a dot edit your list and return None; functions build something new and leave the original alone. sort/sorted and reverse/[::-1] are the same pair, twice.

key= — sort by your rule

Python sorts numbers by size and words alphabetically. key= says "no — sort by this instead":

words = ['banana', 'kiwi', 'apple', 'watermelon', 'fig'] words.sort() print(words) # alphabetical — the default words.sort(key=len) print(words) # shortest first words.sort(key=len, reverse=True) print(words) # longest first
['apple', 'banana', 'fig', 'kiwi', 'watermelon'] ['fig', 'kiwi', 'apple', 'banana', 'watermelon'] ['watermelon', 'banana', 'apple', 'kiwi', 'fig']
figlen 3
kiwilen 4
applelen 5
bananalen 6
watermelonlen 10
💡 key=len — no brackets after len. You are not calling it; you are handing the function to sort and saying "run this on each item, and order by whatever comes out".

Why it exists — capital letters ruin alphabetical order:

names = ['danny', 'Moshe', 'suzi', 'Sharon'] print(sorted(names)) # capitals jump to the front print(sorted(names, key=str.lower)) # what a human expects
['Moshe', 'Sharon', 'danny', 'suzi'] ['danny', 'Moshe', 'Sharon', 'suzi']
key=Sorts byTypical use
lenhow long each item iswords, names, lists inside a list
str.lowerthe lowercased textany list of names typed by a human
absdistance from zerotemperatures, errors, differences
intthe numeric value of a string['10', '9', '2']
temps = [-7, 3, -1, 12, -20] print(sorted(temps)) # [-20, -7, -1, 3, 12] print(sorted(temps, key=abs)) # [-1, 3, -7, 12, -20] nums_as_text = ['10', '9', '2', '33'] print(sorted(nums_as_text)) # ['10', '2', '33', '9'] ← text! print(sorted(nums_as_text, key=int)) # ['2', '9', '10', '33']
⚠️ '10' sorts before '2' because text compares character by character. Numbers that arrived from input() or .split() are strings — convert them, or sort with key=int.
💡 Coming later: when no ready-made function fits, you write the rule inline with lambda — words.sort(key=lambda w: w[-1]) sorts by last letter. You do not need it yet, but you have now seen it.

b = a does not copy a list

With a number this behaves exactly as you expect. With a list it does not — and this is not a bug:

a = [1, 2, 3] b = a # looks like a copy. it is not. b.append(4) print('a =', a) print('b =', b)
a = [1, 2, 3, 4] b = [1, 2, 3, 4]

We never touched a, and a changed. b = a did not build a second list — it hung a second name on the one list that already existed:

a
b
one list, in memory
[1, 2, 3, 4]

Proving it — is asks a different question than ==:

a = [1, 2, 3] b = a c = [1, 2, 3] # a different list that looks the same print(a == b, a is b) # True True print(a == c, a is c) # True False
OperatorAsksThink of it as
==do they hold the same values?"do these two houses look identical?"
isare they the same object?"is it the same house?"

A real copy — three spellings, all identical:

b = a.copy() # the clearest — say what you mean b = a[:] # a slice of everything is a new list b = list(a) # build a new list out of a b.append(4) print(a, b, a is b)
[1, 2, 3] [1, 2, 3, 4] False
⚠️ Where this bites for real: you write backup = grades then grades.sort() — and backup comes out sorted too, because there was only ever one list. Fix it with backup = grades.copy(), or skip the copy and use sorted(grades).

.clear() — and why not just = []

Two ways to empty a list. They print the same thing and they are not the same thing:

a.clear() — empties the list
a = [1, 2, 3] b = a a.clear() print(a) print(b)
[] [] ← b sees it too
a = [] — moves the name
a = [1, 2, 3] b = a a = [] print(a) print(b)
[] [1, 2, 3] ← nothing emptied

.clear() reaches into the list and throws out its contents — everyone pointing at it sees an empty list. = [] never touches the old list; it builds a new empty one and re-points your name at it:

a
b

The case that costs people an afternoon — a list living inside another list:

💡 There is a quieter reason too: inside a loop, lst = [] builds a brand new list every single round and abandons the old one. lst.clear() reuses the same object. Never matters on ten items; matters on ten million.
⚠️ Rule of thumb: if anyone else can see the list, use .clear(). If the list is entirely yours and nobody else knows about it, = [] is fine — and arguably clearer to read.
