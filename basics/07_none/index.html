None & the _ 🕳️

Every tracker needs a starting value — but what do you start at when any number is possible? None is Python's official word for "there is nothing here yet", and it is what separates a program that lies (max = 0) from one that tells the truth. Along the way, meet _ — the variable name that means "I will never look at this".

max.py
best = None if best is None or n > best: best = n

The Problem: What Do You Start At?

💡 When the possible values are bounded — a grade is always 0..100 — a sentinel like max_grade = -1 is fine. None is what you reach for when they are not.

None Is Not Zero, and Not ""

None is a value of its own kind. It means the absence of a value — which is a very different thing from the number zero or an empty piece of text.

Nonenothing at all — "not set yet"no: None + 1 crashes
>>> None + 1 TypeError: unsupported operand type(s) for +: 'NoneType' and 'int' >>> None > 5 TypeError: '>' not supported between instances of 'NoneType' and 'int' >>> print(None) None
⚠️ Capital N, always. none is an undefined name (NameError) and "None" in quotes is just a five-letter string.
🖨️ Printing it is perfectly fine — print(None) shows None. If nothing ever happened, saying None out loud is exactly the right report.
3

Testing for It — is None

There is only ever one None inside a running Python program, so the question "is this variable empty?" is asked with is, not ==.

✅ the Python way
if best is None: print('nothing yet') if best is not None: print(best)
works, but nobody writes it
if best == None: print('nothing yet') if best != None: print(best)
🧠 == asks "same value?". is asks "literally the same object?". For None those are the same question, and is None is the style every Python programmer expects to read.
4

The Pattern: is None or …

Here is the shape you will write for the rest of your programming life — a max tracker that starts empty:

max_number = None while True: num = input('number?') if num == 'exit': break num = int(num) if max_number is None or num > max_number: max_number = num print(f'max: {max_number}')
number?-4 number?-9 number?exit max: -4
⚠️ The order of the two tests is not decoration. Python evaluates or left to right and stops the moment one side is True, so on the first round it never reaches num > max_number. Write them the other way around and you get TypeError: '>' not supported between instances of 'int' and 'NoneType'.
💡 That behaviour is called short-circuit evaluation — the same rule that lets you write if n != 0 and 100 / n > 5: without ever dividing by zero.
5

A Sum That Starts at Nothing

A sum is easier: total = 0 is usually right, because the sum of no numbers is zero. Use None only when the task demands that "no numbers at all" look different from "they added up to 0".

empty sum = 0
total = 0 # in the loop: total += num
empty sum = None
total = None # in the loop: if total is None: total = num else: total += num
⚠️ You cannot write total += num on the first round when total is None — that is a TypeError. The whole if/else exists to handle that one round.
6

The Throwaway _ 🗑️

A for loop must name its counter, even when the loop is pure repetition. When the body never looks at that counter, name it _: an ordinary variable name that carries a message — "I am not going to use this".

the counter matters
for i in range(1, 4): print(f'round {i}')
round 1 round 2 round 3
just repeat 3 times
for _ in range(3): print('hello')
hello hello hello
💡 Nothing about _ is magic — Python treats it like any other name. It is a convention, and a good one: your editor stops warning about an unused variable, and a reader knows at a glance that this loop is only counting rounds.
